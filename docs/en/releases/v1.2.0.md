# v1.2.0 template release notes

**Status:** final. **Release date:** 2026-10-29. **Content version:** SRAS
1.2.0. **Release:** v1.2.0 template release.

This is a **template release**, not a standard release. The repository is an
AI-maintained concern template. An adopting project decides which concerns
apply, how to implement them, and what formal documents or reviews it needs.

The v1.2.0 tag and GitHub Release are created from the release commit on `main`
on 2026-10-29. The release notes are the changelog. There is no `CHANGELOG.md`.

## Release version

The template release version is **1.2.0**. The version is consistent in:

- `package.json`
- `package-lock.json` (the root `version` and `packages[""].version`)
- `src/sras/version.ts`
- `CITATION.cff`
- `core/sras.yaml`
- `docs/.vitepress/config.ts`

`node tools/check-version.ts 1.2.0` passes. `CITATION.cff` `date-released` and
`core/sras.yaml` `released_at` are `2026-10-29`.

## Highlights

- The documentation site now carries an accessibility statement in English and
  Thai. It states the WCAG 2.2 Level AA target, what the automated check covers,
  what it does not cover, and that no manual or assistive-technology testing has
  been performed.
- `npm run check:a11y` runs axe-core over every page in the built site, limited
  to the WCAG 2.0, 2.1, and 2.2 Level A and AA rule tags. It runs in the
  `docs-build` CI job after `npm run docs:build`, and a violation fails the
  build.
- The VitePress appearance switch now has an accessible name in the
  server-rendered HTML. The theme sets the label in a client-only effect, so the
  build adds `aria-label` at render time and the check fails if that stops
  applying.
- `SECURITY.md` records the reporting route, supported versions, scope, response
  expectations, and a dated table of the eight development-only advisories. The
  shipped graph still reports none.
- `templates/ai-assessment/prompt.md` is a copyable prompt for drafting one
  requirement assessment. It injects the requirement's assessment guidance, the
  project scope, the existing evidence IDs, and the files to read, and it
  requires every evidence reference to already exist in the evidence index.
- The documentation site is kept out of search indexes. `robots.txt` disallows
  every crawler and the pages carry `noindex` metadata.
- `README.md` and `CONTRIBUTING.md` list `npm run check:a11y` in the local gate.

The content keeps 167 active requirements: 70 Core, 52 technical module, and 45
Thailand overlay requirements. The 27 register entries and 8 informative
crosswalks are unchanged.

## New requirements

The five technical modules contain 52 active requirements:

A module is a delta on the Core and does not duplicate Core requirements

## Overlays

The four Thailand overlays contain 45 deltas:

- Finance
- E-commerce
- Logistics

An overlay may add, override, or waive a non-gate requirement. A gate
requirement cannot be waived. Every overlay has a `not_covered` section and a
review checklist.

## Breaking changes

None. No requirement ID, schema shape, CLI command, or gate semantic changed in
1.2.0.

The accessibility check and the AI assessment prompt are additions. An existing
project instance keeps its assessment; only version metadata and the lockfile
change.

## Migration

An existing 1.1.0 project instance updates its version metadata and lockfile:

```bash
npm ci
# set sras_version: 1.2.0 in assurance.yaml and assessment.yaml
npm run sras -- project refresh <project-directory>
npm run sras -- project validate <project-directory>
npm run sras -- project resolve <project-directory>
```

`project refresh` recomputes the lockfile for the new standard version.
`project validate` checks the instance and its lockfile. `project resolve`
lists the unassessed gates. No requirement ID, schema field, or gate decision
needs to change for this release.

The [upgrade guide](../templates/upgrade-1x.md) records the expected output and
the failure modes.

## Limitations

These limitations are part of the release, not a footnote:

- **Thai translation is partial.** All 167 active requirements are
  `translation_status: partial` with `machine_translated: true`. No named human
  Thai reviewer has confirmed them.
- **No external or human review is claimed.** The content is AI-authored and
  AI-audited. An adopting project may commission its own review.
- **Registers are unverified.** They are a factual index, not a legal opinion
  or a compliance finding.
- **Legal concerns are desk research.** #128–#131 collect sources and
  questions. They do not decide whether a source applies to a project.
- **The template is generic.** It does not encode agency-specific procurement,
  records, or approval rules. Add those rules in the private instance.
- **The accessibility check is structural.** It evaluates WCAG A and AA rules
  that do not need a layout engine or assistive technology. It does not test
  colour contrast, keyboard operation, focus order, zoom and reflow, or
  screen-reader output, and no manual or assistive-technology test was
  performed.
- **No certification or compliance claim.** The repository is not certified,
  accredited, audited, or approved by a regulator, and it makes no promise
  about a procurement outcome.
- **No service-level agreement.** The maintainer supports the latest v1.x line
  on a best-effort basis.
- **Windows is not tested.** The commands and the `~` examples assume a POSIX
  shell; use WSL2 on Windows.

The template release is created only when:
