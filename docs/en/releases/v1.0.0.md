# v1.0.0 release notes (draft)

**Status:** draft — **not released**. **Prepared:** 2026-10-28. **Content
version in the repository:** SRAS 0.9.0. **Planned release version:** 1.0.0.

The repository has not cut a v1.0.0 release. The version remains 0.9.0, the
milestone is open, and the release is blocked by the human Thai review and the
external human review recorded in
[v1.0.0 readiness](../governance/v1-readiness.md). This page is prepared by #64
and will be published only after #61 and #66 close and the milestone closes.
It is not an announcement and must not be presented as a released standard.

The release notes are the changelog. There is no `CHANGELOG.md`.

## Highlights

- A starter kit for evidence-based software delivery, with a copyable project
  template and a private project-instance workflow.
- 167 active requirements: 70 Core, 52 technical module, and 45 Thailand
  overlay requirements.
- Five technical modules: AI/GenAI, integration and API, regulated data,
  cloud/SaaS, and on-premises.
- Four Thailand sector overlays: finance, e-commerce, logistics, and public
  sector. A gate requirement cannot be waived by an overlay.
- 27 regulatory register entries: 12 Thailand, 6 ASEAN, and 9 EU, with official
  sources and review dates.
- Seven informative crosswalks to external standards.
- A TypeScript CLI for `init`, `project validate`, `project refresh`,
  `project resolve`, `render`, and `guard`.
- Deterministic reference pages and a public-content guard.
- A bilingual English and Thai documentation site.

## New requirements

No new requirement is planned for the 1.0.0 freeze. The release freezes the
SRAS 0.9.0 content and does not add or remove a requirement ID.

If #61 changes an ID, a schema, or a gate, this section and the migration
section must be revised before the release. A content change is not silently
included in a freeze.

## Modules

The five technical modules contain 52 active requirements:

- AI/GenAI
- Integration and API
- Regulated data
- Cloud/SaaS
- On-premises

A module is a delta on the Core and does not duplicate Core requirements
without an explicit relationship.

## Overlays

The four Thailand overlays contain 45 deltas:

- Finance
- E-commerce
- Logistics
- Public sector

An overlay may add, override, or waive a non-gate requirement. A gate
requirement cannot be waived. Every overlay has a `not_covered` section and a
review checklist.

## Registers and crosswalks

The registers contain 27 entries:

- 12 Thailand entries.
- 6 ASEAN entries.
- 9 EU entries.

All entries remain `review_status: unverified`. They cite official sources and
record a review date, but they are not legal advice and do not decide whether an
instrument applies to a project. A project records its own decision and obtains
qualified advice when the risk or the law requires it.

The seven crosswalks are informative mappings. They do not replace the source
standard.

WCAG 2.2 and the NIST AI Risk Management Framework 1.0 are cited by requirements
as external standards, not registered as instruments. The policy is in
[GOVERNANCE.md](https://github.com/yutna/software-delivery-assurance/blob/main/GOVERNANCE.md)
under "Adding a register entry".

## Breaking changes

No breaking change is planned for 1.0.0. The freeze keeps the 0.9.0 IDs, schema
shapes, and gate semantics.

A breaking change would require a major version, a deprecation notice in at
least one prior minor release, a migration guide, and a review cycle. A gate

[review policy](../governance/review-policy.md) and

for the maintenance rules.

## Migration

No migration is planned from SRAS 0.9.0 to 1.0.0 because the freeze does not
change an ID, schema, or gate.

For an existing project instance:

```bash
npm ci
npm run sras -- project validate <project-directory>
npm run sras -- project refresh <project-directory>
npm run sras -- project resolve <project-directory>
```

`project validate` checks the instance and its lockfile. `project refresh`
recomputes the lockfile when the instance changes. A project that uses a
different version should read the migration note for that version; none exists
for 1.0.0 at this draft stage.

If #61 records a schema or gate change, this section must add the affected IDs
and fields, the required instance changes, and the validation command before
the release.

## Limitations

These limitations are part of the release, not a footnote:

- **Thai translation is partial.** All 167 active requirements are
  `translation_status: partial` with `machine_translated: true`. No named human
  Thai reviewer has confirmed them.
- **No external human review.** The v0.9.0 AI self-review is not independent,
  not human, and not a substitute for external review. It does not make v1.0.0
  ready.
- **Registers are unverified.** They are a factual index, not a legal opinion
  or a compliance finding.
- **Legal concerns are desk research.** #128–#131 collect sources and
  questions. They do not decide whether a source applies to a project.
- **The template is generic.** It does not encode agency-specific procurement,
  records, or approval rules. Add those rules in the private instance.
- **No certification or compliance claim.** The repository is not certified,
  accredited, audited, or approved by a regulator, and it makes no promise
  about a procurement outcome.
- **No service-level agreement.** The maintainer supports the latest v1.x line
  on a best-effort basis.

## Customer-facing summary

> The SRAS starter kit is an open, evidence-based template for software delivery
> assurance. It provides 167 active requirements across a Core, five technical
> modules, and four Thailand sector overlays, plus 27 regulatory register
> entries, seven informative crosswalks, a project-instance CLI, deterministic
> reference pages, and a content guard. It is usable with limitations: the Thai
> translation is machine-assisted and partial, the registers are unverified, and
> no external human review has been completed. It is not a certification, not
> legal advice, and not evidence of compliance. Teams should record their own
> scope, evidence, claims, and risks in a private project instance.

This summary uses verified repository statements only. It does not name a
customer, a real project, or a reviewer.
