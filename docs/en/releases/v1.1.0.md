# v1.1.0 template release notes

**Status:** final. **Release date:** 2026-10-28. **Content version:** SRAS
1.1.0. **Release:** v1.1.0 template release.

This is a **template release**, not a standard release. The repository is an
AI-maintained concern template. An adopting project decides which concerns
apply, how to implement them, and what formal documents or reviews it needs.

The v1.1.0 tag and GitHub Release are created from the release commit on `main`
on 2026-10-28. The release notes are the changelog. There is no `CHANGELOG.md`.

## Release version

The template release version is **1.1.0**. The version is consistent in:

- `package.json`
- `package-lock.json` (the root `version` and `packages[""].version`)
- `src/sras/version.ts`
- `CITATION.cff`
- `core/sras.yaml`
- `docs/.vitepress/config.ts`

`node tools/check-version.ts 1.1.0` passes. `CITATION.cff` `date-released` and
`core/sras.yaml` `released_at` are `2026-10-28`.

## Highlights

- Generated requirement pages now show rationale, lite and full assessment
  guidance, external references, and every crosswalk that maps the requirement.
  Each crosswalk has a generated page, and the reference index lists them.
- An adopter operations guide covers private CI validation with a pinned
  library tag, a 1.x upgrade procedure, and a walkthrough of the synthetic
  end-to-end example.
- A targeted NIST SP 800-218 (SSDF) 1.1 crosswalk adds the secure software
  development practices that the requirements cite, with explicit coverage
  gaps. The crosswalk count is 8.
- `sras init` writes `Not signed` for `signoff.name` and `signoff.role`, and
  `project validate` warns without failing a legitimate draft.
- `check-version` verifies `package-lock.json`, including
  `packages[""].version`.
- Feature request and bug report forms ask for the fields that
  `CONTRIBUTING.md` already requires, and `CITATION.cff` carries software
  citation metadata.
- The v1.0.0 documentation corrections from #191 are included since the 1.0.0
  tag.

The content keeps 167 active requirements: 70 Core, 52 technical module, and 45
Thailand overlay requirements. The 27 register entries are unchanged.

## Overlays

The four Thailand overlays contain 45 deltas:

- Finance

- Logistics

An overlay may add, override, or waive a non-gate requirement. A gate
requirement cannot be waived. Every overlay has a `not_covered` section and a
review checklist.

## Registers and crosswalks

The registers contain 27 entries: 12 Thailand, 6 ASEAN, and 9 EU. Every entry
names an official source and a review date and stays `review_status:
unverified`.

The informative crosswalks are:

- ISO/IEC 27001:2022
- ISO/IEC 42001:2023
- NIST AI Risk Management Framework 1.0
- NIST Cybersecurity Framework 2.0
- NIST SP 800-218 (SSDF) 1.1
- OWASP ASVS 5.0

A crosswalk is informative. It is not an equivalence, a certification, or a
compliance claim. The SSDF crosswalk records the practices it does not cover in

## Breaking changes

None. No requirement ID, schema shape, or gate semantic changed in 1.1.0.

The unsigned sign-off is a behaviour addition for newly generated instances.
Existing instances keep their recorded sign-off and remain valid. A sentinel
warning is non-fatal, so a draft still passes `project validate`.

## Migration

An existing 1.0.0 project instance updates its version metadata and lockfile:

```bash
npm ci
# set sras_version: 1.1.0 in assurance.yaml and assessment.yaml
npm run sras -- project refresh <project-directory>
npm run sras -- project validate <project-directory>
npm run sras -- project resolve <project-directory>
```

`project refresh` recomputes the lockfile for the new standard version.
`project validate` checks the instance and its lockfile. `project resolve`
lists the unassessed gates. No requirement ID, schema field, or gate decision
needs to change for this release.

The [upgrade guide](../templates/upgrade-1x.md) records the expected output and
the failure modes.

## Limitations

These limitations are part of the release, not a footnote:

- **Thai translation is partial.** All 167 active requirements are
  `translation_status: partial` with `machine_translated: true`. No named human
  Thai reviewer has confirmed them.
- **No external or human review is claimed.** The content is AI-authored and
  AI-audited. An adopting project may commission its own review.
- **Registers are unverified.** They are a factual index, not a legal opinion
  or a compliance finding.
- **Legal concerns are desk research.** #128–#131 collect sources and
  questions. They do not decide whether a source applies to a project.
- **The template is generic.** It does not encode agency-specific procurement,
  records, or approval rules. Add those rules in the private instance.
- **No certification or compliance claim.** The repository is not certified,
  accredited, audited, or approved by a regulator, and it makes no promise
  about a procurement outcome.
- **No service-level agreement.** The maintainer supports the latest v1.x line
  on a best-effort basis.
- **Windows is not tested.** The commands and the `~` examples assume a POSIX
  shell; use WSL2 on Windows.

## Release conditions

The template release is created only when:

- every 1.1.0 milestone issue is closed;
- #192 sets the version to 1.1.0 and updates the release metadata;
- the release notes and announcement state the limitations;
- `node tools/check-version.ts 1.1.0` passes;
- `ci-ok` and `pr-check / check` are green on `main`;
- `oss-kit doctor` reports no drift.

No human Thai review, external review, or legal review is a release condition.

If a condition had not been met, the release would have stayed open and this
page would have stayed a draft. The milestone is not closed to make the
checklist look complete.
