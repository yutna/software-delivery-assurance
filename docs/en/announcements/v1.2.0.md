# v1.2.0 template release announcement

**Status:** final for the v1.2.0 template release on 2026-10-29.
**Content version:** SRAS 1.2.0. **Release:** v1.2.0 template release.

This is a **template release**, not a standard release. The announcement uses
verified repository statements. It does not name a customer, a real project, a
reviewer, a date that has not happened, or a sign-off that does not exist.

## Short announcement

> The Software Delivery Assurance project has published the 1.2.0 template
> release of its SRAS starter kit. The release adds an accessibility statement
> and an automated accessibility check for the documentation site, a refreshed
> security policy, and a copyable AI assessment prompt that injects each
> requirement's assessment guidance and project scope. The kit provides 167
> active requirements across a Core, five technical modules, and four Thailand
> sector overlays, plus 27 regulatory register entries, eight informative
> crosswalks, a project-instance CLI, deterministic reference pages, and a
> content guard. It is usable with limitations. The Thai translation is
> machine-assisted and partial, the registers are unverified, the accessibility
> check is structural only, and no external or human review is claimed. The kit
> is not a standard, not a certification, not legal advice, and not evidence of
> compliance.

## Who it is for

- Thai government digital teams, state enterprises, and vendors delivering
  public services.
- Product owners, engineering leads, security and privacy teams, operations
  teams, assessors, and bid teams.
- Finance, e-commerce, and logistics teams that need the same evidence
  discipline.
- Teams already running a 1.1.0 instance that need the upgrade path.
- Teams that want an AI assistant to draft an assessment without letting it
  invent evidence.

## What the release contains

- A copyable project template and a private project-instance workflow.
- The SRAS Core with 70 active requirements.
- Five technical modules with 52 requirements: AI/GenAI, integration and API,
  regulated data, cloud/SaaS, and on-premises.
- Four Thailand sector overlays with 45 deltas: finance, e-commerce, logistics,
  and public sector.
- 27 regulatory register entries: 12 Thailand, 6 ASEAN, and 9 EU.
- Eight informative crosswalks.
- An accessibility statement for the documentation site, with the target, the
  known limitations, and the feedback route.
- An automated axe-core check over every built page, limited to the WCAG 2.0,
  2.1, and 2.2 A/AA rules, run in CI.
- A security policy with a dated record of the development-only advisories.
- An AI assessment prompt template and guide, in English and Thai.
- A TypeScript CLI for `init`, `project validate`, `project refresh`,
  `project resolve`, `render`, and `guard`.
- A bilingual English and Thai documentation site.
- Deterministic reference pages and a content guard.

## What changed since 1.1.0

- The documentation site has an accessibility statement and an automated check.
- The server-rendered theme switch now has an accessible name.
- `SECURITY.md` records scope, supported versions, response expectations, and the
  development-only advisories.
- `templates/ai-assessment/prompt.md` and its guide are available.
- The documentation site is kept out of search indexes.
- No requirement ID, schema shape, CLI command, or gate semantic changed.

## What it does not claim

- It is not a certification, accreditation, audit attestation, or regulatory
  approval.
- It is not legal advice or a definitive statement of legal compliance.
- It is not a published standard with external sign-off.
- No external human reviewer has been engaged. The AI audit is not independent
  and is not a substitute for external review.
- The Thai translation is `translation_status: partial` with
  `machine_translated: true`. No named human Thai reviewer has confirmed it.
- The 27 register entries are `review_status: unverified`.
- The four legal concerns are desk research notes, not legal opinions.
- The accessibility check does not test colour contrast, keyboard operation,
  focus order, zoom and reflow, or screen-reader output, and no manual or
  assistive-technology test was performed.
- The template is generic. It does not encode agency-specific procurement,
  records, or approval rules.

## Where to start

1. Read [template readiness](../governance/template-readiness.md).
2. Follow the [quick start](../quick-start.md).
3. Read the [owner map](../templates/owner-map.md) and the
   [project template guide](../templates/project.md).
4. Draft an assessment with the
   [AI assessment prompt](../templates/ai-assessment.md), and review every
   result before recording it.
5. Validate the instance in CI with the
   [adopter operations guide](../templates/ci-validation.md).
6. If you run a 1.1.0 instance, follow the
   [1.x upgrade procedure](../templates/upgrade-1x.md).

The public repository holds templates and synthetic examples only. Real
evidence and customer data stay in the private instance.
