## Description

Informative crosswalk from SRAS Core requirements to WCAG 2.2 Level AA success criteria and conformance sections. Accessibility-specific requirements are planned for sector overlays in v0.4.0. This crosswalk is not an accessibility conformance claim.

**Thai:** crosswalk เชิงข้อมูลจากข้อกำหนด SRAS Core ไปยัง success criteria และหมวด conformance ของ WCAG 2.2 Level AA ข้อกำหนดเฉพาะด้าน accessibility มีแผนอยู่ใน sector overlays ใน v0.4.0 crosswalk นี้ไม่ใช่การอ้างความสอดคล้องด้าน accessibility

This crosswalk is informative. It is not an equivalence, a certification, or a compliance claim.

## Mappings

- `SRAS-CHG-004` — `5.2 Conformance Requirements` (related) — Automated tests cannot confirm accessibility conformance; manual and assistive-technology testing are required.
- `SRAS-CHG-008` — `5.3 Conformance Claims` (related) — Release evidence should state the accessibility target and known limitations.
- `SRAS-GOV-001` — `5.2 Conformance Requirements` (partial) — Scope approval should name the accessibility target; the accessibility requirements themselves belong to overlays.
- `SRAS-GOV-008` — `5.3 Conformance Claims` (related) — A conformance claim is a published claim and needs evidence; SRAS claim control is broader.
- `SRAS-INC-003` — `1.1.1 Non-text Content` (related) — Incident communication should provide text alternatives for non-text content.
- `SRAS-OPS-010` — `4.1.3 Status Messages` (partial) — Service status updates should be exposed as accessible status messages.
- `SRAS-PRV-003` — `3.3.1 Error Identification, 3.3.3 Error Suggestion` (related) — Request forms should identify and explain errors accessibly.
- `SRAS-PRV-006` — `3.1.1 Language of Page, 3.1.5 Reading Level` (related) — A privacy notice should declare its language and be readable.
