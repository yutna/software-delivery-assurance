# ข้อกังวลทางกฎหมายและกฎระเบียบ

**Desk research:** 2026-10-28 **จัดทำโดย:** AI execution agent
**สถานะ:** ไม่ใช่คำแนะนำทางกฎหมาย ไม่ผ่านการตรวจทานโดยนักกฎหมายไทยที่มี
คุณสมบัติ และไม่ใช่การวินิจฉัยว่าแหล่งอ้างอิงใดใช้กับโปรเจกต์ของคุณ

starter kit นี้เป็น template สำหรับรวบรวมคำถาม แหล่งอ้างอิงทางการ และประเด็น
ที่ทีมโปรเจกต์ต้องตัดสินใจ ไม่ได้ออกใบรับรอง อนุมัติ หรือตอบคำถามทางกฎหมายแทน
โปรเจกต์ ทีมต้องตัดสินใจว่าอะไรใช้กับ scope ของตน บันทึกการตัดสินใจ และขอ
คำแนะนำจากผู้เชี่ยวชาญเมื่อความเสี่ยงหรือกฎหมายกำหนด

issue ที่เกี่ยวข้องจะปิดเมื่อ "เผยแพร่ research note" แล้ว การปิด issue ไม่ใช่การ
ลงนามทางกฎหมาย และไม่ได้หมายความว่าแหล่งอ้างอิงนั้นใช้กับโปรเจกต์ของคุณ

> หน้านี้เป็นฉบับภาษาไทยที่แปลโดยเครื่องและปรับถ้อยคำ ยังไม่ผ่านการตรวจทาน

## วิธีใช้หน้านี้

1. หาข้อกังวลที่กระทบโปรเจกต์
2. อ่านสรุปแหล่งอ้างอิงและเปิดแหล่งทางการ
3. บันทึกการตัดสินใจของโปรเจกต์ใน private instance ใช้ template ด้านล่าง
4. ถ้าโปรเจกต์อยู่ในภาคกำกับดูแล เป็นบริการสาธารณะ อยู่ในกระบวนการจัดซื้อ หรือ
   มีข้อมูลส่วนบุคคล/ข้อมูลอ่อนไหว ให้ขอคำแนะนำจากนักกฎหมายไทยที่มีคุณสมบัติ
   หรือหน่วยงานกำกับดูแลที่เกี่ยวข้อง
5. ห้ามนำ note ไปใส่ใน claim สาธารณะราวกับเป็นความเห็นทางกฎหมาย เพราะ library
   ไม่รู้จักโปรเจกต์ สัญญา หรือแนวปฏิบัติของหน่วยงานของคุณ

## 1. การอนุมัติ cloud และ outsourcing (`TH-FIN-003`)

**คำถาม.** การใช้ cloud หรือ outsourcing แบบ material ต้องแจ้งหรือขออนุมัติ
ธนาคารแห่งประเทศไทยล่วงหน้าหรือไม่ และข้อเท็จจริงใดเปลี่ยนคำตอบ

**แหล่งอ้างอิงระบุว่า.**

- ประกาศธนาคารแห่งประเทศไทย **สกช. 5/2566** เรื่องหลักเกณฑ์การกำกับดูแลความเสี่ยง
  ด้านเทคโนโลยีสารสนเทศ (16 ตุลาคม 2566 เผยแพร่ 30 ตุลาคม 2566) กำหนดให้ธนาคาร
  พาณิชย์แจ้ง ธปท. ล่วงหน้าอย่างน้อย 15 วันก่อนการใช้หรือเปลี่ยนแปลงเทคโนโลยี
  สารสนเทศที่มีนัยสำคัญ รวมถึงกรณีใช้บริการ เชื่อมต่อ หรือให้บุคคลภายนอกเข้าถึง
  ข้อมูล ส่วนสถาบันการเงินเฉพาะกิจ บริษัทเงินทุน และบริษัทเครดิตฟองซิเอร์ต้อง
  ขออนุญาตก่อน ประกาศไม่ได้ใช้คำว่า cloud ในข้อความนั้น แต่การนำ cloud มาใช้อาจเป็น
  การเปลี่ยนแปลงที่มีนัยสำคัญ
  [ประกาศ ธปท.](https://www.bot.or.th/content/dam/bot/fipcs/documents/FOG/2566/ThaiPDF/25660202.pdf),
  [ราชกิจจานุเบกษา](https://ratchakitcha.soc.go.th/documents/10342.pdf)
- ประกาศ ธปท. **FPG. 19/2559** เรื่อง IT outsourcing (28 ธันวาคม 2559) อธิบาย
  รูปแบบแจ้งหรือขออนุมัติล่วงหน้า 30 วันสำหรับ critical IT outsourcing และ
  cloud โดยแยก private cloud, public cloud, ผู้ให้บริการในกลุ่มและนอกกลุ่ม
  [คำแปลภาษาอังกฤษอย่างไม่เป็นทางการ](https://www.bot.or.th/content/dam/bot/fipcs/documents/FPG/2560/EngPDF/25600035.pdf)
- แหล่งทั้งสองมีโครงสร้างและวันที่ต่างกัน desk review นี้ไม่ได้วินิจฉัยว่า
  ประกาศใดใช้กับสถาบันใดในปัจจุบัน หรือมีปฏิสัมพันธ์กันอย่างไรหลังการแก้ไข
  ประกาศในภายหลัง

**สิ่งที่ยังไม่ชัด.**

- การเปลี่ยนแปลงนั้นเป็น "significant IT use or change" ของสถาบันหรือไม่
- สถาบันเป็นธนาคารพาณิชย์ สถาบันการเงินเฉพาะกิจ บริษัทเงินทุน หรือประเภทอื่น
- cloud เป็น private, public หรือ hybrid และผู้ให้บริการอยู่ในกลุ่มเดียวกันหรือไม่
- ประกาศ outsourcing ฉบับเก่ายังมีผลอย่างไรหลังประกาศ IT risk ปี 2566

**คำถามสำหรับที่ปรึกษา.**

- ประกาศฉบับใดและข้อใดใช้กับสถาบันและรูปแบบนี้
- ต้องแจ้ง ขออนุมัติ หรือไม่ต้องทำอะไร
- threshold คืออะไรและบันทึกอย่างไร
- ต้องยื่นล่วงหน้ากี่วันก่อน go-live
- ต้องมี risk assessment และการอนุมัติจากคณะกรรมการรูปแบบใด

**บันทึกการตัดสินใจของโปรเจกต์.** บันทึกประเภทสถาบัน รูปแบบ cloud ระดับ
criticality ช่องทางการยื่น วันที่ และคำแนะนำที่ได้รับใน private instance

## 2. ระยะเก็บรักษาบันทึกธุรกรรม (`TH-FIN-004`)

**คำถาม.** กฎหมายไทยฉบับใดกำหนดระยะเก็บรักษาขั้นต่ำของบันทึกธุรกรรม ระบุ
ระยะเวลาเท่าใด และต่างกันตามประเภทบริการหรือไม่

**แหล่งอ้างอิงระบุว่า.**

- **พระราชบัญญัติป้องกันและปราบปรามการฟอกเงิน พ.ศ. 2542** มาตรา 22 กำหนดให้
  สถาบันการเงินเก็บรักษาข้อมูลการแสดงตน 5 ปีนับจากปิดบัญชีหรือยุติความสัมพันธ์
  และเก็บรักษาบันทึกธุรกรรมและบันทึกข้อเท็จจริงตามมาตรา 21 เป็นเวลา 5 ปีนับจาก
  วันที่ทำธุรกรรมหรือบันทึกข้อเท็จจริง มาตรา 22/1 กำหนดให้เก็บข้อมูล CDD 10 ปี
  [พระราชบัญญัติฉบับทางการ](https://sed.amlo.go.th/uploads/tiny/Law%20and%20regulaiton/Act/AMLA%20Act.pdf)
- สำนักงานป้องกันและปราบปรามการฟอกเงินเผยแพร่แนวทางที่ย้ำระยะ 5 ปีและ 10 ปี
  สำหรับผู้มีหน้าที่รายงาน
  [แนวทาง ปปง.](https://sed.amlo.go.th/content/detail/113)
- สำนักงาน ก.ล.ต. กำหนดให้ผู้ประกอบธุรกิจสินทรัพย์ดิจิทัลเก็บรักษาบันทึกอย่างน้อย
  5 ปี โดย 2 ปีแรกต้องพร้อมให้ตรวจสอบ และมีแนวทาง 5 ปีในบันทึกของธุรกิจหลักทรัพย์
  เช่นกัน
  [ข่าว ก.ล.ต.](https://www.sec.or.th/EN/Pages/News_Detail.aspx?SECID=10957),
  [ประกาศ ก.ล.ต.](https://publish.sec.or.th/nrs/10275s.pdf)

**สิ่งที่ยังไม่ชัด.**

- บริการนั้นเป็นผู้มีหน้าที่รายงานตามกฎหมายฟอกเงิน ธุรกิจหลักทรัพย์ สินทรัพย์
  ดิจิทัล ประกันภัย หรือกิจกรรมอื่นที่อยู่ภายใต้กฎเฉพาะหรือไม่
- กฎเฉพาะภาคส่วนกำหนดระยะยาวกว่า 5 ปีหรือไม่
- ระยะเริ่มนับจากวันใดสำหรับบันทึกแต่ละประเภท
- กฎหมายบัญชี ภาษี หรือการเก็บรักษาอื่นเพิ่มข้อกำหนดแยกหรือไม่

**คำถามสำหรับที่ปรึกษา.**

- กฎหมายใดใช้กับบริการและบันทึกประเภทนี้
- ระยะขั้นต่ำคือเท่าใดและเริ่มนับเมื่อใด
- บันทึกนี้เป็น transaction record, customer identification record หรือ
  due diligence record
- กฎเฉพาะภาคส่วนกำหนดระยะยาวกว่าหรือรูปแบบการเข้าถึงหรือไม่
- ต้องเก็บที่ไหนและอย่างไร

**บันทึกการตัดสินใจของโปรเจกต์.** บันทึกประเภทบริการ ประเภทบันทึก กฎหมาย
ระยะเวลา วันที่เริ่มต้น สถานที่เก็บ และคำแนะนำที่ได้รับ

## 3. เงื่อนไข licence ของ open data (`TH-PUB-005`)

**คำถาม.** แนวทางราชการไทยยอมรับเงื่อนไข licence แบบใดสำหรับ open government
data และมีรายการ licence ที่เผยแพร่โดยแหล่งทางการหรือไม่

**แหล่งอ้างอิงระบุว่า.**

- **DGA Open Government License** เวอร์ชัน 1.0 (10 มิถุนายน 2564) ใช้กับข้อมูล
  ที่เผยแพร่บนแพลตฟอร์ม data.go.th ให้สิทธิแบบ non-exclusive ไม่มีค่าใช้จ่าย
  ในการใช้ คัดลอก เผยแพร่ แจกจ่าย และประมวลผลข้อมูล ภายใต้วัตถุประสงค์ที่ชอบด้วย
  กฎหมายและการอ้างอิงแหล่งที่มา โดยมีข้อยกเว้นสำหรับข้อมูลที่ห้ามเปิดเผย
  ตราสัญลักษณ์ทางการ เครื่องหมายทหาร และทรัพย์สินทางปัญญาของบุคคลภายนอก
  [ข้อกำหนด DGA Open Government License](https://data.go.th/th/pages/dga-open-government-license)
- แนวทาง metadata ของ DGA กำหนดหมวด licence **G0–G5** ได้แก่ Open Data Common,
  Creative Commons Attribution, Attribution-NonCommercial,
  Attribution-ShareAlike, Attribution-NonCommercial-ShareAlike,
  Attribution-NoDerivs, Attribution-NonCommercial-NoDerivs และ licence อื่น
  การเลือกขึ้นกับชั้นข้อมูล อนุญาตให้ใช้เชิงพาณิชย์หรือไม่ อนุญาตให้ดัดแปลง
  หรือไม่ และต้องอ้างอิงหรือไม่
  [แนวทาง licence DGA](https://gdhelppage.gdcatalog.go.th/p00_03_new7.html)
- DGA Open Government Data Guideline เวอร์ชัน 2.0 (มรด. 8:2567) อธิบายมาตรฐาน
  metadata และการเผยแพร่ชุดข้อมูลภาครัฐ
  [มาตรฐาน DGA](https://standard.dga.or.th/standard/)

**สิ่งที่ยังไม่ชัด.**

- เจ้าของชุดข้อมูลเลือก licence ใดและ metadata บันทึกถูกต้องหรือไม่
- ชุดข้อมูลมีข้อมูลส่วนบุคคล ทรัพย์สินทางปัญญาของบุคคลภายนอก หรือองค์ประกอบที่
  ห้ามเปิดเผยหรือไม่
- โปรเจกต์ต้องการใช้เชิงพาณิชย์ ดัดแปลง หรือเผยแพร่ต่อหรือไม่ และ licence ที่เลือก
  อนุญาตหรือไม่
- สัญญาจัดซื้อหรือนโยบายหน่วยงานเพิ่มเงื่อนไข licence หรือไม่

**คำถามสำหรับที่ปรึกษา.**

- ชุดข้อมูลเป็นข้อมูลสาธารณะที่เปิดภายใต้ licence ได้หรือไม่
- หมวด G0–G5 ใดตรงกับการนำไปใช้ที่ต้องการ
- licence อนุญาตการใช้เชิงพาณิชย์หรือการดัดแปลงหรือไม่
- ต้องใส่ข้อความอ้างอิงอย่างไร
- ชุดข้อมูลมีสิทธิของบุคคลภายนอกหรือข้อมูลส่วนบุคคลหรือไม่

**บันทึกการตัดสินใจของโปรเจกต์.** บันทึกชุดข้อมูล ชั้นข้อมูล licence ที่เลือก
ข้อความอ้างอิง การใช้ที่อนุญาต แหล่งอ้างอิง และคำแนะนำที่ได้รับ

## 4. เวอร์ชันและระดับ WCAG (`TH-PUB-003`)

**คำถาม.** มาตรฐานและแนวทางราชการไทยระบุ WCAG เวอร์ชันและระดับใดสำหรับบริการ
สาธารณะ และแตกต่างตามประเภทหน่วยงานหรือไม่

**แหล่งอ้างอิงระบุว่า.**

- **มาตรฐานเว็บไซต์ภาครัฐ เวอร์ชัน 3.0** (มสพร 11-2566) ของ DGA อ้างอิง WCAG
  เอกสารแนวทางกล่าวถึง WCAG 2.1 และ 2.2 และระบุว่าข้อกำหนดสำหรับหน่วยงานรัฐ
  ไม่ได้ระบุมาตรฐานเดียวเจาะจง แต่แนะนำ WCAG 2.1 ระดับ AA เนื่องจากครอบคลุม
  กรณีส่วนใหญ่
  [แนวทาง DGA](https://standard.dga.or.th/wp-content/uploads/2023/07/Final_PRD_0.1_DGA-6-4-256X_Gov.-Website-1.pdf)
- บทความแนวทางของ DGA ระบุว่าหน่วยงานรัฐควรมุ่งมั่นอย่างน้อยระดับ AA
  [บทความ DGA](https://standard.dga.or.th/article/5837/)
- **TWCAG 2025** ของสภาดิจิทัลฯ อ้างอิง WCAG 2.2 ส่วน TWCAG 2022 อ้างอิง WCAG
  2.1 และ W3C เผยแพร่ WCAG 2.2 เป็นมาตรฐานแนะนำฉบับปัจจุบัน
  [TWCAG 2025](https://www.dct.or.th/upload/downloads/1747741860AccessibilityGuideline2025V.3.1Final.pdf),
  [WCAG 2.2](https://www.w3.org/TR/WCAG22/),
  [คำแปลไทย WCAG 2.2](https://www.nectec.or.th/standard/WCAG/REC-WCAG22-20231005-TH/)

**สิ่งที่ยังไม่ชัด.**

- desk review นี้ไม่พบตราสารทางกฎหมายฉบับเดียวในแหล่งที่ตรวจซึ่งกำหนดเวอร์ชัน
  และระดับเดียวที่ผูกพันกับบริการภาครัฐไทยทุกประเภท
- นโยบายหน่วยงาน สัญญาจัดซื้อ หรือหน่วยงานกำกับดูแลอาจกำหนดเวอร์ชันหรือระดับ
  ที่เฉพาะเจาะจง
- คำตอบอาจต่างกันสำหรับหน่วยงานกลาง องค์กรปกครองส่วนท้องถิ่น รัฐวิสาหกิจ และ
  บริการที่ผู้ขายส่งมอบ
- โปรเจกต์อาจเลือกระดับสูงกว่าที่แนวทางแนะนำ แต่ควรบันทึกเหตุผล

**คำถามสำหรับที่ปรึกษา.**

- หน่วยงานมีนโยบาย มาตรฐาน หรือข้อสัญญาที่ระบุ WCAG เวอร์ชันและระดับหรือไม่
- service journey ใดอยู่ในขอบเขต
- ระดับ AA เพียงพอหรือบางเนื้อหาต้องใช้ AAA
- สัญญาและการทดสอบรับงานจะใช้เวอร์ชันใด
- ใครบันทึก target ที่ตกลงและหลักฐานการทดสอบ

**บันทึกการตัดสินใจของโปรเจกต์.** บันทึก scope บริการ WCAG version ระดับ
conformance ฐานอ้างอิง วิธีการทดสอบ owner และวันทบทวน

## Template บันทึกการตัดสินใจของโปรเจกต์

คัดลอกบล็อกนี้ไปไว้ใน private project instance ห้ามใส่คำแนะนำทางกฎหมายจริง
ข้อมูลลูกค้า หรือข้อมูลลับใน repository สาธารณะ

```text
Concern:
Project and scope:
Why this concern applies (or why not):
Source reviewed (title, issuer, date, URL):
Decision:
Advice obtained (name, role, organisation, date):
Residual risk and owner:
Review due:
```

## เมื่อใดควรยกระดับ

ขอคำแนะนำที่มีคุณสมบัติก่อนอ้างอิง desk note เมื่อโปรเจกต์:

- เป็นสถาบันการเงิน ธุรกิจหลักทรัพย์ ประกันภัย ผู้ให้บริการชำระเงิน หรือองค์กร
  ที่อยู่ภายใต้การกำกับดูแล
- ต้องแจ้งหรือขออนุมัติ ธปท.
- เป็นการจัดซื้อภาครัฐหรือบริการที่เปิดให้ประชาชนใช้
- เกี่ยวข้องกับข้อมูลส่วนบุคคล ข้อมูลอ่อนไหว ข้อมูลการเงิน หรือข้อมูลข้ามพรมแดน
- จะกล่าวอ้างต่อสาธารณะเรื่อง compliance, accessibility หรือ open data
- มีสัญญา การอนุมัติจากคณะกรรมการ หรือการยื่นต่อหน่วยงานกำกับดูแลที่ขึ้นกับคำตอบ

## หน้านี้ไม่ใช่อะไร

- ไม่ใช่คำแนะนำทางกฎหมาย
- ไม่ใช่ความเห็นทางกฎหมายหรือการวินิจฉัยการนำไปใช้
- ไม่ใช่การรับรอง การอนุมัติ หรือถ้อยแถลง compliance
- ไม่ใช่สิ่งทดแทนแหล่งอ้างอิงทางการ สัญญาของโปรเจกต์ หรือคำแนะนำของนักกฎหมายไทย
  หรือหน่วยงานกำกับดูแลที่มีคุณสมบัติ
