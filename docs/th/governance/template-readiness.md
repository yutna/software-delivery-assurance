# ความพร้อมของ template

**เส้นทาง:** template / starter kit **สถานะ:** ใช้ได้โดยมีข้อจำกัด
**เนื้อหาเวอร์ชัน:** SRAS 1.1.0 **release:** v1.1.0 template release
2026-10-28 **บันทึกเมื่อ:** 2026-10-28

หน้านี้บอกว่าวันนี้ทีมใช้ส่วนใดได้จริง และต้องไม่กล่าวอ้างอะไร เป็นจุดเริ่มต้น
ของ template บันทึก AI audit มีการตรวจและข้อจำกัดที่เกี่ยวข้อง

> หน้านี้เป็นฉบับภาษาไทยที่แปลโดยเครื่องและปรับถ้อยคำ ยังไม่ผ่านการตรวจทาน
> โดยมนุษย์ จึงยังคง `translation_status: partial` และ `machine_translated: true`

## "ใช้ได้โดยมีข้อจำกัด" หมายถึงอะไร

starter kit เหมาะกับการวางแผนภายใน การประเมินโปรเจกต์ การติดตามหลักฐาน
การจัดการช่องว่าง และการเตรียมบันทึก assurance ส่วนตัว แต่ไม่เหมาะเป็นฐานเดียว
สำหรับการตัดสินใจจัดซื้อ การรับรอง ข้อความว่าปฏิบัติตามกฎหมาย การอนุมัติเปิด
บริการต่อสาธารณะ หรือความเห็น assurance จากภายนอก

"ใช้ได้โดยมีข้อจำกัด" เป็นข้อความบอกตำแหน่งของสินค้า ไม่ใช่การรับรอง
ไม่ได้หมายความว่าเนื้อหา stable แล้ว การแปลไทยสมบูรณ์แล้ว หรือผู้ตรวจทาน
ภายนอกอนุมัติเนื้อหาแล้ว

## พร้อมใช้ตอนนี้

| ความสามารถ                        | สถานะ  | สิ่งที่รองรับ                                                        |
| --------------------------------- | ------ | -------------------------------------------------------------------- |
| Clone, build และรันการตรวจ        | พร้อม  | CI และคำสั่งตรวจสอบใน README                                         |
| สร้าง instance แบบ lite หรือ full | พร้อม  | `sras init`, schema validation และ tests                             |
| ตรวจ instance ที่แก้ไขแล้ว        | พร้อม  | `sras project validate <dir>` อ่านอย่างเดียวและล้มเหลวเมื่อ lock ล้า |
| ตรวจความครบของประเภทหลักฐาน       | พร้อม  | requirement ที่ `verified` ต้องมีหลักฐานครบทุกประเภทที่คาดหวัง       |
| Refresh lockfile                  | พร้อม  | `sras project refresh <dir>` เขียนเฉพาะ lockfile                     |
| ดู resolution และ coverage        | พร้อม  | `sras project resolve <dir>` แสดงทุก gate ที่ยังไม่ถูกประเมิน        |
| บันทึกหน่วยงานผู้ว่าจ้างภาครัฐ    | พร้อม  | `scope.public_sector` พร้อม contracting authority และ contract       |
| Core, module และ overlay          | มีอยู่ | ข้อกำหนด Core 70, module 52 และ overlay 45 ใน SRAS 1.1.0             |
| ทะเบียนและ crosswalk ไทย          | มีอยู่ | ทะเบียนไทย 12 รายการและ crosswalk 8 ชุด                              |
| Reference pages แบบ deterministic | พร้อม  | `sras render --check`                                                |
| Content guard สาธารณะ             | พร้อม  | `sras guard` และ CI annotations                                      |

## ข้อจำกัดที่ต้องวางแผนรับมือ

| ข้อจำกัด               | ผลต่อโปรเจกต์                                                       | สิ่งที่เจ้าของต้องทำ                                                 |
| ---------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------- |
| การแปลไทยยัง partial   | ข้อกำหนด active 167 ข้อเป็น machine-assisted และยังไม่ผ่านมนุษย์    | ใช้ภาษาอังกฤษเป็นฉบับหลัก โปรเจกต์ตัดสินใจเองว่าจะตรวจภาษาไทยหรือไม่ |
| ทะเบียนยัง unverified  | รายการชี้แหล่งทางการแต่ไม่ใช่คำแนะนำทางกฎหมายหรือข้อสรุป compliance | ปรึกษาผู้เชี่ยวชาญกฎหมายหรือ regulatory focal point                  |
| ยังไม่มีการทบทวนภายนอก | ยังไม่มีผู้ตรวจทานอิสระตรวจเนื้อหา                                  | โปรเจกต์จะจัดให้มีการทบทวนเองได้ ห้ามอ้างว่ามีที่นี่                 |
| ข้อกังวลกฎหมายมี note  | note รวบรวมแหล่งทางการและคำถาม แต่ไม่ได้ตัดสินแทนโปรเจกต์           | อ่าน [ข้อกังวลทางกฎหมาย](legal-concerns.md) และบันทึกการตัดสินใจเอง  |
| Template เป็นแบบกลาง   | ไม่มีกฎจัดซื้อ การเก็บรักษา หรือการอนุมัติเฉพาะหน่วยงาน             | เพิ่มกฎเฉพาะใน instance ส่วนตัว ไม่ใช่ใน repository นี้              |

Legal concern notes ได้แก่ `#128`, `#129`, `#130` และ `#131` ซึ่งรวบรวมแหล่ง
อ้างอิงทางการและคำถาม ไม่ใช่ความเห็นทางกฎหมายและไม่ตัดสินแทนโปรเจกต์ finding
ที่เลื่อนทั้งห้ารายการจาก v0.9.0 ถูกแก้ครบแล้ว: `#140`, `#141`, `#135`, `#134`
และ `#126`

WCAG 2.2 และ NIST AI Risk Management Framework 1.0 เป็นมาตรฐานภายนอก ไม่ใช่
รายการทะเบียน กฎและแหล่งอ้างอิงทางการอยู่ใน
[ทะเบียน](../registers/index.md)

## เงื่อนไขขั้นต่ำก่อนใช้งานจริง

1. มี executive sponsor ที่ระบุชื่อและยอมรับ scope กับความเสี่ยงคงเหลือ
2. กรอก [owner map](../templates/owner-map.md) ด้วยชื่อบทบาทจริง
3. project instance เป็นส่วนตัวและหลักฐานอยู่นอก repository นี้
4. มี legal หรือ regulatory focal point ตรวจทะเบียนและ
   [ข้อกังวลทางกฎหมาย](legal-concerns.md) ที่กระทบโปรเจกต์
5. โปรเจกต์ตัดสินใจเองว่าจะใช้ผู้ตรวจทานภาษาไทยที่เป็นมนุษย์สำหรับเนื้อหาที่
   จะเผยแพร่หรือใช้ในการตัดสินใจทางการหรือไม่
6. ทีมบันทึก claims, ช่องว่าง, owner และ due date ไว้ใน instance ไม่ใช่เพียงใน
   บันทึกการประชุม

## เส้นทางการนำไปใช้

```text
อ่านหน้านี้
    -> มอบหมายเจ้าของ (owner map)
    -> สร้าง instance (quick start)
    -> กำหนด scope และ selection
    -> ประเมินและอ้างอิงหลักฐาน
    -> validate และ refresh lockfile
    -> ตรวจ claims และ risks
    -> ลงนามใน instance ส่วนตัว
```

template track จบที่การลงนามใน instance ส่วนตัว ไม่ได้ออกใบรับรองสาธารณะหรือ
การอนุมัติระดับมาตรฐาน

## เมื่อโปรเจกต์ต้องการ formal process ของตนเอง

library นี้ไม่ได้ให้มาตรฐาน การรับรอง หรือ formal review หากโปรเจกต์ต้องการ
สิ่งเหล่านี้ ให้ทำในบริบทของตนเอง

- การทบทวนภาษาไทยโดยมนุษย์สำหรับเนื้อหาที่จะเผยแพร่
- บันทึกการทบทวนจากภายนอกหรือผู้ตรวจที่เป็นอิสระ
- ความเห็นทางกฎหมายต่อทะเบียนหรือข้อกังวลทางกฎหมาย
- ข้อความทางการว่าโปรเจกต์ (ไม่ใช่ repository นี้) ผ่านการทบทวนแล้ว

[External review packet](external-review-packet.md) และ
[Thai review kit](thai-review-kit.md) เป็นเครื่องมือทางเลือกสำหรับงานของ
โปรเจกต์นั้น ไม่ใช่ข้อบังคับในการใช้ template

## Confidence labels ในหน้านี้

- ข้อความเกี่ยวกับคำสั่งและจำนวนเป็น **checked** จากคำสั่งตรวจสอบของ repository
  ให้รันใหม่ ณ commit ของคุณ จำนวนอาจเปลี่ยน
- คำอธิบายเนื้อหาเป็น **documented** จาก repository
- การตัดสินว่าหมาะสมเป็น **provisional** จนกว่าโปรเจกต์จริงจะใช้งาน
- template release v1.1.0 เป็น **published** และการตัดสินว่าหมาะสมยังเป็น
  **provisional**

อ่าน [confidence labels](confidence-labels.md) สำหรับข้อตกลงนี้
