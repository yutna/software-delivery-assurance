# Module และ overlay

module และ overlay ทั้งคู่เป็นส่วนเพิ่มของ SRAS Core ไม่ใช่สำเนามาตรฐานทั้งชุด
ทั้งคู่ถูกเลือกใน `assurance.yaml` และ pin ไว้ใน lockfile

## Module ทางเทคนิค

เลือก module เมื่อผลิตภัณฑ์มีลักษณะที่เกี่ยวข้อง

- `SRAS-AI` — AI และ GenAI, 12 ข้อกำหนด เลือกเมื่อมีฟีเจอร์ AI หรือ
  generative AI, การตัดสินใจที่ AI ช่วย หรือระบบอัตโนมัติ
- `SRAS-INT` — integration และ API, 10 ข้อกำหนด เลือกเมื่อมี API,
  partner integration หรือการแลกเปลี่ยนระหว่างระบบ
- `SRAS-RGD` — regulated data, 10 ข้อกำหนด เลือกเมื่อมีข้อมูลส่วนบุคคล
  ข้อมูลทางการเงิน หรือข้อมูลที่มีกฎกำกับ
- `SRAS-CLD` — cloud/SaaS, 10 ข้อกำหนด เลือกเมื่อพึ่งพา cloud หรือ SaaS,
  มี multi-tenancy หรือมีคำถามเรื่อง data residency
- `SRAS-ONP` — on-premises, 10 ข้อกำหนด เลือกเมื่อทีมดูแลโครงสร้างพื้นฐาน
  ที่ติดตั้งเอง

module เพิ่มข้อกำหนดเท่านั้น ไม่ลดทอนข้อกำหนด Core

## Overlay ภาคธุรกิจ

overlay เป็นส่วนเพิ่มตามเขตอำนาจหรืออุตสาหกรรม สามารถเพิ่ม เข้มงวดขึ้น หรือ
ยกเว้นข้อกำหนดที่ไม่ใช่ gate พร้อมเหตุผล แต่ยกเว้น gate ไม่ได้

- `TH-FIN` — การเงินประเทศไทย, 10 ข้อกำหนด สำหรับธนาคาร ประกันภัย
  ผู้ให้บริการชำระเงิน fintech และซอฟต์แวร์การเงิน
- `TH-ECM` — อีคอมเมิร์ซประเทศไทย, 12 ข้อกำหนด สำหรับตลาดออนไลน์
  แพลตฟอร์มขายตรงถึงผู้บริโภค checkout และการจัดการคำสั่งซื้อ
- `TH-LOG` — โลจิสติกส์ประเทศไทย, 11 ข้อกำหนด สำหรับการขนส่ง คลังสินค้า
  การติดตาม การเชื่อมต่อศุลกากร และการจัดส่ง
- `TH-PUB` — ภาครัฐประเทศไทย, 12 ข้อกำหนด สำหรับหน่วยงานของรัฐ รัฐวิสาหกิจ
  และผู้ขายบริการภาครัฐ

ทุก overlay ระบุสิ่งที่ไม่ครอบคลุม overlay ไม่ใช่ความเห็นทางกฎหมาย และการเพิ่ม
overlay ไม่ได้ทำให้ผลิตภัณฑ์ปฏิบัติตามกฎหมาย

## กฎการเลือก

- เลือกทุก module ที่มีลักษณะตรงกับผลิตภัณฑ์ อย่าเลือกไม่ครบเพราะการประเมิน
  ยังเร็วอยู่
- เลือกทุก overlay ของเขตอำนาจและอุตสาหกรรมที่อยู่ในขอบเขต
- บันทึกการเลือกทั้งใน `assurance.yaml` และ assessment ทั้งสองไฟล์ต้องตรงกัน
- ข้อกำหนดที่ไม่ใช้ให้บันทึกเป็น `not_applicable` พร้อมเหตุผล ไม่ใช่ลบออก
- gate ยกเว้นไม่ได้ ทางเดียวคือเปลี่ยน scope ที่บันทึกไว้พร้อมการอนุมัติจาก
  owner และอธิบายว่าเหตุใดข้อกำหนดจึงไม่ใช้
- การยกเว้นข้อกำหนดที่ไม่ใช่ gate ต้องมีเหตุผลเป็นลายลักษณ์อักษร risk owner
  วันหมดอายุ และการอนุมัติ

## ไฟล์อยู่ที่ใด

- `modules/<module>/module.yaml` — ข้อมูล module และข้อกำหนด
- `overlays/industries/<sector>/` — ข้อมูล overlay ข้อกำหนด และบันทึกการตรวจ
- `core/domains/*.yaml` — ข้อกำหนด Core
- `schemas/` — JSON Schema สำหรับทุกวัตถุ

[Reference](../reference/index.md) ที่ generate ไว้แสดงข้อกำหนดทั้งหมด รวมถึง
ข้อกำหนดของ module และ overlay

## สิ่งที่ overlay ไม่ใช่

- ไม่ใช่กฎหมายหรือกฎระเบียบ
- ไม่ใช่คำแนะนำทางกฎหมายหรือข้อสรุปด้าน compliance
- ไม่ใช่มาตรฐานเต็ม แต่เป็นส่วนเพิ่มบน Core
- ไม่ใช่การรับรองผู้ขาย

บันทึกข้อเท็จจริงของกฎหมายหรือกฎระเบียบอยู่ใน
[ทะเบียน](../registers/index.md) ไม่ใช่ใน overlay

มาตรฐานภายนอกที่สมัครใจซึ่งอ้างเพื่อเป็นแนวทางประเมินอยู่ใน references ของ
ข้อกำหนด ไม่ใช่รายการทะเบียน เว้นแต่กฎหมายให้ผลผูกพัน ดู
[มาตรฐานภายนอกในทะเบียน](../registers/index.md)
