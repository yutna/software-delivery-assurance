# Release notes template v1.2.0

**สถานะ:** final **วันที่เผยแพร่:** 2026-10-29 **เวอร์ชันเนื้อหา:** SRAS 1.2.0
**release:** template release v1.2.0

นี่คือ **template release** ไม่ใช่ standard release ส่วน repository นี้เป็น
concern template ที่ดูแลโดย AI โปรเจกต์ที่นำไปใช้ตัดสินใจเองว่าข้อกังวลใดใช้กับ
บริบทของตน จะ implement อย่างไร และต้องมีเอกสารทางการหรือการทบทวนอะไร

tag v1.2.0 และ GitHub Release สร้างจาก release commit บน `main` เมื่อ
2026-10-29 ส่วน release notes นี้คือ changelog ไม่มี `CHANGELOG.md`

## เวอร์ชันของ release

เวอร์ชันของ template release คือ **1.2.0** และตรงกันในไฟล์เหล่านี้

- `package.json`
- `package-lock.json` (ทั้ง root `version` และ `packages[""].version`)
- `src/sras/version.ts`
- `CITATION.cff`
- `core/sras.yaml`
- `docs/.vitepress/config.ts`

`node tools/check-version.ts 1.2.0` ผ่าน ส่วน `CITATION.cff` `date-released`
และ `core/sras.yaml` `released_at` เป็น `2026-10-29`

## ไฮไลต์

- เว็บไซต์เอกสารมี accessibility statement ทั้งภาษาอังกฤษและภาษาไทย ระบุเป้าหมาย
  WCAG 2.2 Level AA สิ่งที่ check อัตโนมัติครอบคลุม สิ่งที่ไม่ครอบคลุม และระบุว่า
  ยังไม่มีการทดสอบด้วยมือหรือ assistive technology
- `npm run check:a11y` รัน axe-core กับทุกหน้าในเว็บไซต์ที่ build แล้ว เฉพาะ rule
  ระดับ A และ AA ของ WCAG 2.0, 2.1 และ 2.2 รันใน CI job `docs-build` หลัง
  `npm run docs:build` และ violation ทำให้ build fail
- ปุ่มสลับ theme ของ VitePress มี accessible name ใน HTML ที่ render จาก server
  แล้ว เพราะ theme ตั้ง label ใน effect ฝั่ง client เท่านั้น ฝั่ง build จึงเติม
  `aria-label` ตอน render และ check จะ fail ถ้าสิ่งนี้หยุดทำงาน
- `SECURITY.md` บันทึกช่องทางแจ้งปัญหา เวอร์ชันที่รองรับ scope ความคาดหวังเรื่อง
  การตอบกลับ และตาราง advisory ที่มีวันที่ของชุด development-only ทั้งแปดรายการ
  ส่วน shipped graph ยังรายงานว่าไม่มี
- `templates/ai-assessment/prompt.md` เป็น prompt ที่คัดลอกได้สำหรับร่างการประเมิน
  หนึ่งข้อกำหนด โดยใส่ assessment guidance ของข้อกำหนดนั้น scope ของโปรเจกต์
  evidence ID ที่มีอยู่ และรายการไฟล์ที่ต้องอ่านเข้าไปในตัว และบังคับให้
  evidence reference ทุกรายการมีอยู่แล้วใน evidence index
- เว็บไซต์เอกสารถูกกันออกจาก search index โดย `robots.txt` disallow crawler
  ทุกราย และหน้าเพจมี metadata `noindex`
- `README.md` และ `CONTRIBUTING.md` ระบุ `npm run check:a11y` ใน local gate

เนื้อหายังคง requirement ที่ใช้งานอยู่ 167 ข้อ: Core 70, module ทางเทคนิค 52 และ
overlay ประเทศไทย 45 ส่วนทะเบียน 27 รายการและ crosswalk เชิงข้อมูล 8 ชุดไม่เปลี่ยน

## requirement ใหม่

ไม่มี requirement ถูกเพิ่ม ลบ หรือเปลี่ยนเลขสำหรับ 1.2.0 release นี้คง requirement
ID, schema shape และ gate semantics ของ SRAS 1.0.0 ไว้

## Modules

module ทางเทคนิคทั้งห้ามี requirement ที่ใช้งานอยู่ 52 ข้อ

- AI/GenAI
- Integration and API
- Regulated data
- Cloud/SaaS
- On-premises

module เป็น delta บน Core และไม่ทำซ้ำ requirement ของ Core โดยไม่มีความสัมพันธ์
ที่ระบุไว้

## Overlays

overlay ประเทศไทยทั้งสี่มี delta 45 ข้อ

- Finance
- E-commerce
- Logistics
- Public sector

overlay อาจเพิ่ม override หรือ waive requirement ที่ไม่ใช่ gate ส่วน requirement
ที่เป็น gate waive ไม่ได้ ทุก overlay มีส่วน `not_covered` และ review checklist

## ทะเบียนและ crosswalk

ทะเบียนมี 27 รายการ: ประเทศไทย 12, อาเซียน 6 และสหภาพยุโรป 9 ทุกรายการระบุ
แหล่งอ้างอิงทางการและวันที่ทบทวน และคงสถานะ `review_status: unverified`

crosswalk เชิงข้อมูลมีดังนี้

- ISO/IEC 27001:2022
- ISO/IEC 42001:2023
- NIST AI Risk Management Framework 1.0
- NIST Cybersecurity Framework 2.0
- NIST SP 800-218 (SSDF) 1.1
- OWASP ASVS 5.0
- PCI DSS 4.0.1
- WCAG 2.2 Level AA

crosswalk เป็นเชิงข้อมูล ไม่ใช่ความเท่าเทียม การรับรอง หรือข้อกล่าวอ้างเรื่อง
compliance

## Breaking changes

ไม่มี requirement ID, schema shape, CLI command หรือ gate semantic ใดเปลี่ยนใน
1.2.0

accessibility check และ AI assessment prompt เป็นส่วนที่เพิ่มเข้ามา project
instance ที่มีอยู่ยังคงการประเมินเดิม มีเพียง version metadata และ lockfile ที่
เปลี่ยน

## Migration

project instance 1.1.0 ที่มีอยู่อัปเดต version metadata และ lockfile

```bash
npm ci
# set sras_version: 1.2.0 in assurance.yaml and assessment.yaml
npm run sras -- project refresh <project-directory>
npm run sras -- project validate <project-directory>
npm run sras -- project resolve <project-directory>
```

`project refresh` คำนวณ lockfile ใหม่สำหรับ standard version ใหม่
`project validate` ตรวจ instance และ lockfile ส่วน `project resolve` แสดง gate
ที่ยังไม่ได้ประเมิน ไม่มี requirement ID, schema field หรือ gate decision ใดที่ต้อง
เปลี่ยนสำหรับ release นี้

[upgrade guide](../templates/upgrade-1x.md) บันทึกผลลัพธ์ที่คาดหวังและ failure
mode ไว้

## ข้อจำกัด

ข้อจำกัดเหล่านี้เป็นส่วนหนึ่งของ release ไม่ใช่เชิงอรรถ

- **คำแปลไทยเป็น partial** requirement ที่ใช้งานอยู่ทั้ง 167 ข้อมี
  `translation_status: partial` และ `machine_translated: true` ยังไม่มีผู้ทบทวน
  ภาษาไทยที่มีชื่อยืนยัน
- **ไม่มีการอ้างการทบทวนจากภายนอกหรือจากมนุษย์** เนื้อหาสร้างและตรวจโดย AI
  โปรเจกต์ที่นำไปใช้อาจว่าจ้างการทบทวนของตนเอง
- **ทะเบียนยัง unverified** เป็นดัชนีข้อเท็จจริง ไม่ใช่ความเห็นทางกฎหมายหรือ
  ข้อค้นพบด้าน compliance
- **ข้อกังวลทางกฎหมายเป็น desk research** #128–#131 รวบรวมแหล่งอ้างอิงและคำถาม
  ไม่ได้ตัดสินว่าแหล่งใดใช้กับโปรเจกต์
- **template เป็นแบบทั่วไป** ไม่ได้เข้ารหัสกฎการจัดซื้อ การเก็บบันทึก หรือการ
  อนุมัติของหน่วยงานใดหน่วยงานหนึ่ง ให้เพิ่มกฎเหล่านั้นใน private instance
- **accessibility check เป็นการตรวจเชิงโครงสร้าง** ตรวจ rule ระดับ A และ AA ที่
  ไม่ต้องใช้ layout engine หรือ assistive technology ไม่ได้ทดสอบ colour contrast,
  การใช้คีย์บอร์ด, ลำดับ focus, zoom และ reflow หรือเอาต์พุตของ screen reader
  และไม่มีการทดสอบด้วยมือหรือ assistive technology
- **ไม่มีข้อกล่าวอ้างเรื่องการรับรองหรือ compliance** repository ไม่ได้ผ่านการ
  รับรอง การให้การรับรอง การตรวจสอบ หรือการอนุมัติจากหน่วยงานกำกับดูแล และไม่ให้
  คำมั่นเกี่ยวกับผลลัพธ์การจัดซื้อ
- **ไม่มี service-level agreement** ผู้ดูแลรองรับ v1.x line ล่าสุดแบบ best-effort
- **ไม่ได้ทดสอบ Windows** คำสั่งและตัวอย่างที่ใช้ `~` สมมติว่าเป็น POSIX shell
  บน Windows ให้ใช้ WSL2

## สรุปสำหรับผู้อ่านภายนอก

> SRAS starter kit เป็น template แบบเปิดที่อิงหลักฐานสำหรับ software delivery
> assurance template release 1.2.0 เพิ่ม accessibility statement และ check
> อัตโนมัติสำหรับเว็บไซต์เอกสาร ปรับปรุง security policy และเพิ่ม AI assessment
> prompt ที่คัดลอกได้ ซึ่งใส่ assessment guidance ของแต่ละ requirement เข้าไปในตัว
> kit มี requirement ที่ใช้งานอยู่ 167 ข้อ ครอบคลุม Core, module ทางเทคนิคห้า
> โมดูล และ overlay ประเทศไทยสี่ชุด พร้อมทะเบียนกฎระเบียบ 27 รายการ และ crosswalk
> เชิงข้อมูล 8 ชุด ใช้ได้โดยมีข้อจำกัด คำแปลไทยเป็นแบบ machine-assisted และ
> partial ทะเบียนยัง unverified accessibility check เป็นการตรวจเชิงโครงสร้าง
> เท่านั้น และไม่มีการอ้างการทบทวนจากภายนอกหรือจากมนุษย์ ไม่ใช่การรับรอง ไม่ใช่
> คำแนะนำทางกฎหมาย และไม่ใช่หลักฐานของ compliance ทีมควรบันทึก scope, หลักฐาน,
> claim และความเสี่ยงของตนเองใน private project instance

สรุปนี้ใช้เฉพาะข้อความที่ตรวจสอบได้จาก repository ไม่ระบุชื่อลูกค้า โปรเจกต์จริง
หรือผู้ทบทวน
