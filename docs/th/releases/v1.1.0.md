# Release notes template v1.1.0

**สถานะ:** final **วันที่เผยแพร่:** 2026-10-28 **เวอร์ชันเนื้อหา:** SRAS 1.1.0
**release:** template release v1.1.0

นี่คือ **template release** ไม่ใช่ standard release ส่วน repository นี้เป็น
concern template ที่ดูแลโดย AI โปรเจกต์ที่นำไปใช้ตัดสินใจเองว่าข้อกังวลใดใช้กับ
บริบทของตน จะ implement อย่างไร และต้องมีเอกสารทางการหรือการทบทวนอะไร

tag v1.1.0 และ GitHub Release สร้างจาก release commit บน `main` เมื่อ
2026-10-28 ส่วน release notes นี้คือ changelog ไม่มี `CHANGELOG.md`

## เวอร์ชันของ release

เวอร์ชันของ template release คือ **1.1.0** และตรงกันในไฟล์เหล่านี้

- `package.json`
- `package-lock.json` (ทั้ง root `version` และ `packages[""].version`)
- `src/sras/version.ts`
- `CITATION.cff`
- `core/sras.yaml`
- `docs/.vitepress/config.ts`

`node tools/check-version.ts 1.1.0` ผ่าน ส่วน `CITATION.cff` `date-released`
และ `core/sras.yaml` `released_at` เป็น `2026-10-28`

## ไฮไลต์

- หน้า requirement ที่สร้างแสดง rationale, แนวทางการประเมิน lite และ full,
  references ภายนอก และ crosswalk ทุกอันที่แมป requirement นั้น crosswalk
  แต่ละอันมีหน้าที่สร้าง และ reference index ลิสต์ไว้
- คู่มือ operations สำหรับ adopter ครอบคลุมการตรวจสอบอินสแตนซ์ส่วนตัวใน CI ด้วย
  tag ของ library ที่ปักไว้ ขั้นตอนอัปเกรด 1.x และ walkthrough ของตัวอย่าง
  end-to-end synthetic
- crosswalk NIST SP 800-218 (SSDF) 1.1 แบบเจาะจงเพิ่มแนวปฏิบัติ secure software
  development ที่ requirement อ้างถึง พร้อมช่องว่างที่ยังไม่ครอบคลุม จำนวน
  crosswalk คือ 8
- `sras init` เขียน `Not signed` ใน `signoff.name` และ `signoff.role` และ
  `project validate` เตือนโดยไม่ทำให้ draft ที่ถูกต้องล้มเหลว
- `check-version` ตรวจ `package-lock.json` รวม `packages[""].version`
- issue form สำหรับ feature request และ bug report ถามฟิลด์ที่ `CONTRIBUTING.md`
  กำหนดไว้แล้ว และ `CITATION.cff` มี metadata สำหรับการอ้างอิงซอฟต์แวร์
- งานแก้เอกสาร v1.0.0 จาก #191 รวมอยู่ตั้งแต่ tag 1.0.0

เนื้อหายังมี 167 requirement ที่ใช้งานอยู่ แยกเป็น Core 70, module 52 และ
overlay ประเทศไทย 45 ส่วนทะเบียน 27 รายการไม่เปลี่ยน

## Requirement ใหม่

ไม่มี requirement ถูกเพิ่ม ลบ หรือเปลี่ยนเลขใน 1.1.0 release นี้ยังคง
requirement ID, schema shape และความหมายของ gate จาก SRAS 1.0.0

## Module

module ทางเทคนิคทั้งห้ามี requirement ที่ใช้งานอยู่ 52 ข้อ

- AI/GenAI
- Integration และ API
- Regulated data
- Cloud/SaaS
- On-premises

module เป็นส่วนเพิ่มจาก Core และไม่ทำซ้ำ requirement ของ Core โดยไม่มี
ความสัมพันธ์ที่ระบุไว้

## Overlay

overlay ประเทศไทยทั้งสี่มีส่วนเพิ่ม 45 ข้อ

- การเงิน
- อีคอมเมิร์ซ
- โลจิสติกส์
- ภาครัฐ

overlay เพิ่ม แทนที่ หรือยกเว้น requirement ที่ไม่ใช่ gate ได้ ส่วน gate
ยกเว้นไม่ได้ ทุก overlay มีส่วน `not_covered` และ review checklist

## ทะเบียนและ crosswalk

ทะเบียนมี 27 รายการ แยกเป็นประเทศไทย 12, อาเซียน 6 และสหภาพยุโรป 9 ทุกรายการ
ระบุแหล่งทางการและวันทบทวน และยังคง `review_status: unverified`

crosswalk เชิงข้อมูลมีดังนี้

- ISO/IEC 27001:2022
- ISO/IEC 42001:2023
- NIST AI Risk Management Framework 1.0
- NIST Cybersecurity Framework 2.0
- NIST SP 800-218 (SSDF) 1.1
- OWASP ASVS 5.0
- PCI DSS 4.0.1
- WCAG 2.2 Level AA

crosswalk เป็นข้อมูล ไม่ใช่ความเท่าเทียม การรับรอง หรือการอ้าง compliance
crosswalk SSDF บันทึกแนวปฏิบัติที่ยังไม่ครอบคลุมไว้ใน description

## Breaking changes

ไม่มี requirement ID, schema shape หรือความหมายของ gate เปลี่ยนใน 1.1.0

unsigned sign-off เป็นการเพิ่มพฤติกรรมสำหรับอินสแตนซ์ที่สร้างใหม่ อินสแตนซ์เดิม
ยังเก็บ sign-off ที่บันทึกไว้และยัง valid คำเตือน sentinel ไม่ทำให้ validation
ล้มเหลว draft จึงยังผ่าน `project validate`

## การย้ายเวอร์ชัน

อินสแตนซ์โปรเจกต์ 1.0.0 ที่มีอยู่อัปเดต metadata และ lockfile ดังนี้

```bash
npm ci
# set sras_version: 1.1.0 in assurance.yaml and assessment.yaml
npm run sras -- project refresh <project-directory>
npm run sras -- project validate <project-directory>
npm run sras -- project resolve <project-directory>
```

`project refresh` คำนวณ lockfile ใหม่สำหรับ standard version ใหม่
`project validate` ตรวจอินสแตนซ์และ lockfile ส่วน `project resolve` แสดง gate
ที่ยังไม่ได้ประเมิน ไม่มี requirement ID, schema field หรือการตัดสินใจเรื่อง gate
ที่ต้องเปลี่ยนสำหรับ release นี้

[คู่มืออัปเกรด](../templates/upgrade-1x.md) บันทึกผลลัพธ์ที่คาดหวังและกรณีที่
ขั้นตอนล้มเหลว

## ข้อจำกัด

ข้อจำกัดเหล่านี้เป็นส่วนหนึ่งของ release ไม่ใช่ footnote

- **คำแปลไทยยัง partial** ข้อกำหนด active 167 ข้อเป็น
  `translation_status: partial` และ `machine_translated: true`
  ยังไม่มีผู้ทบทวนภาษาไทยที่ระบุชื่อยืนยัน
- **ไม่มีการอ้างการทบทวนภายนอกหรือโดยมนุษย์** เนื้อหาเขียนและตรวจโดย AI
  โปรเจกต์ที่นำไปใช้จะจัดให้มีการทบทวนของตนเองได้
- **ทะเบียนยัง unverified** เป็นดัชนีข้อเท็จจริง ไม่ใช่ความเห็นทางกฎหมายหรือ
  ข้อสรุป compliance
- **ข้อกังวลทางกฎหมายเป็น desk research** #128–#131 รวบรวมแหล่งและคำถาม
  ไม่ได้ตัดสินว่าแหล่งใดใช้กับโปรเจกต์
- **Template เป็นแบบกลาง** ไม่มีกฎจัดซื้อ การเก็บรักษา หรือการอนุมัติเฉพาะ
  หน่วยงาน เพิ่มกฎเหล่านั้นในอินสแตนซ์ส่วนตัว
- **ไม่มีการอ้าง certification หรือ compliance** repository ไม่ได้รับการรับรอง
  ไม่ได้ผ่านการ accreditation ไม่ได้ผ่าน audit และไม่ได้รับการอนุมัติจาก
  หน่วยงานกำกับ และไม่ให้คำมั่นเกี่ยวกับผลการจัดซื้อ
- **ไม่มี service-level agreement** maintainer ดูแลสาย v1.x ล่าสุดแบบ
  best-effort
- **ยังไม่ได้ทดสอบ Windows** คำสั่งและตัวอย่างที่ใช้ `~` อ้างถึง POSIX shell
  บน Windows ให้ใช้ WSL2

- #192 ตั้งเวอร์ชันเป็น 1.1.0 และอัปเดต release metadata
- release notes และ announcement ระบุข้อจำกัด
- `node tools/check-version.ts 1.1.0` ผ่าน

## สรุปสำหรับลูกค้า

> SRAS starter kit เป็น template แบบเปิดที่อิงหลักฐานสำหรับการรับประกันการส่งมอบ
> ซอฟต์แวร์ ส่วน template release 1.1.0 มี requirement ที่ใช้งานอยู่ 167 ข้อ
> ครอบคลุม Core, module ทางเทคนิคห้าโมดูล และ overlay ประเทศไทยสี่ชุด
> พร้อมทะเบียนกฎระเบียบ 27 รายการ, crosswalk เชิงข้อมูล 8 ชุด, หน้า requirement
> ที่สร้างพร้อมข้อมูลครบขึ้น, คู่มือ operations สำหรับ adopter และ CLI สำหรับ
> project instance ใช้ได้โดยมีข้อจำกัด คำแปลไทยเป็นแบบ machine-assisted และ
> partial ทะเบียนยัง unverified และไม่มีการอ้างการทบทวนภายนอกหรือโดยมนุษย์
> ไม่ใช่การรับรอง ไม่ใช่คำแนะนำทางกฎหมาย และไม่ใช่หลักฐานของ compliance
> ทีมควรบันทึก scope, หลักฐาน, claim และความเสี่ยงของตนเองในอินสแตนซ์ส่วนตัว

สรุปนี้ใช้ข้อความที่ตรวจสอบได้จาก repository เท่านั้น ไม่ระบุชื่อลูกค้า โปรเจกต์จริง
หรือผู้ทบทวน
