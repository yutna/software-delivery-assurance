# Release notes v1.0.0 template release

**สถานะ:** final **วันที่ release:** 2026-10-28 **เวอร์ชันเนื้อหา:** SRAS
1.0.0 **Release:** v1.0.0 template release

นี่เป็น **template release** ไม่ใช่ standard release ส่วน repository นี้เป็น
concern template ที่ดูแลโดย AI โปรเจกต์ที่นำไปใช้ตัดสินใจเองว่าข้อกังวลใดใช้กับ
บริบทของตน จะ implement อย่างไร และต้องมีเอกสารหรือการทบทวนทางการอะไร

พอ milestone v1.0.0 ปิด tag v1.0.0 และ GitHub Release ก็จะถูกสร้าง
release notes นี้ทำหน้าที่เป็น changelog ไม่มี `CHANGELOG.md`

## เวอร์ชัน release

เวอร์ชัน template release คือ **1.0.0** และตรงกันใน:

- `package.json`
- `package-lock.json`
- `src/sras/version.ts`
- `CITATION.cff`
- `core/sras.yaml`
- `docs/.vitepress/config.ts`

`node tools/check-version.ts 1.0.0` ผ่าน และ `CITATION.cff` `date-released`
กับ `core/sras.yaml` `released_at` เป็น `2026-10-28`

## ไฮไลต์

- starter kit สำหรับการส่งมอบซอฟต์แวร์ที่อิงหลักฐาน พร้อม project template
  ที่คัดลอกได้และ workflow ของ project instance ส่วนตัว
- ข้อกำหนด active 167 ข้อ: Core 70, technical module 52 และ overlay ประเทศไทย 45
- technical module ห้าโมดูล: AI/GenAI, integration และ API, regulated data,
  cloud/SaaS และ on-premises
- overlay ภาคธุรกิจประเทศไทยสี่ชุด: การเงิน อีคอมเมิร์ซ โลจิสติกส์ และภาครัฐ
  overlay ยกเว้น gate ไม่ได้
- register 27 รายการ: ประเทศไทย 12, อาเซียน 6 และสหภาพยุโรป 9
  พร้อมแหล่งอ้างอิงทางการและวันที่ทบทวน
- crosswalk เชิงข้อมูลเจ็ดชุดไปยังมาตรฐานภายนอก
- TypeScript CLI สำหรับ `init`, `project validate`, `project refresh`,
  `project resolve`, `render` และ `guard`
- reference pages แบบ deterministic และ content guard สำหรับเนื้อหาสาธารณะ
- documentation site สองภาษา English และไทย

## ข้อกำหนดใหม่

ไม่มีข้อกำหนดเพิ่มหรือลดใน template release 1.0.0 ส่วน release นี้คง ID, schema
shape และ gate semantics ของ SRAS 0.9.0

## Modules

technical module ห้าโมดูลมีข้อกำหนด active 52 ข้อ:

- AI/GenAI
- Integration และ API
- Regulated data
- Cloud/SaaS
- On-premises

module เป็น delta ของ Core และไม่ทำซ้ำข้อกำหนด Core โดยไม่มีความสัมพันธ์ที่
ระบุชัดเจน

## Overlays

overlay ประเทศไทยสี่ชุดมี delta 45 ข้อ:

- การเงิน
- อีคอมเมิร์ซ
- โลจิสติกส์
- ภาครัฐ

overlay เพิ่มข้อกำหนด override ข้อกำหนดเดิม หรือยกเว้นข้อกำหนดที่ไม่ใช่ gate ได้
แต่ยกเว้น gate ไม่ได้ ทุก overlay มีส่วน `not_covered` และ review checklist

ช่วง `extends` ของ overlay เป็น `>=0.3.0 <2.0.0` ใน release นี้ทำให้ overlay
ทั้งสี่ resolve กับ SRAS 1.0.0 ได้ ส่วนเนื้อหาข้อกำหนดไม่เปลี่ยน

## Registers และ crosswalks

register มี 27 รายการ:

- ประเทศไทย 12 รายการ
- อาเซียน 6 รายการ
- สหภาพยุโรป 9 รายการ

ทุกรายการยังเป็น `review_status: unverified` ชี้แหล่งอ้างอิงทางการและบันทึกวันที่
ทบทวน แต่ไม่ใช่คำแนะนำทางกฎหมายและไม่ตัดสินว่ากฎหมายหรือมาตรฐานใดใช้กับโปรเจกต์
โปรเจกต์บันทึกการตัดสินใจของตนเองและขอคำแนะนำที่มีคุณสมบัติเมื่อความเสี่ยงหรือ
กฎหมายกำหนด

crosswalk ทั้งเจ็ดชุดเป็น mapping เชิงข้อมูล ไม่ใช่การแทนมาตรฐานต้นทาง

WCAG 2.2 และ NIST AI Risk Management Framework 1.0 ถูกอ้างโดยข้อกำหนดเป็น
มาตรฐานภายนอก ไม่ได้ลงทะเบียนเป็นกฎหมายหรือมาตรฐานที่มีผลผูกพัน นโยบายอยู่ใน
[GOVERNANCE.md](https://github.com/yutna/software-delivery-assurance/blob/main/GOVERNANCE.md)
หัวข้อ "Adding a register entry"

## Breaking changes

ไม่มี ID, schema shape หรือ gate semantics เปลี่ยนใน 1.0.0 ส่วน release นี้เป็น
ขอบเขตเวอร์ชันและ metadata ของ template ไม่ใช่การเขียนเนื้อหาใหม่

ถ้ามี breaking change ในอนาคต ต้องใช้ major version, deprecation notice ใน
minor release ก่อนอย่างน้อยหนึ่งครั้ง, migration guide และ review cycle
ข้อกำหนดที่เป็น gate จะไม่ถูกลบโดยไม่แจ้ง
ดู[นโยบายการทบทวน](../governance/review-policy.md) และ
[GOVERNANCE.md](https://github.com/yutna/software-delivery-assurance/blob/main/GOVERNANCE.md)
สำหรับกฎการดูแล

## Migration

อินสแตนซ์โปรเจกต์ที่ใช้ 0.9.0 อัปเดต metadata เวอร์ชันและ lockfile:

```bash
npm ci
# ตั้ง sras_version: 1.0.0 ใน assurance.yaml และ assessment.yaml
npm run sras -- project refresh <project-directory>
npm run sras -- project validate <project-directory>
npm run sras -- project resolve <project-directory>
```

`project refresh` คำนวณ lockfile ใหม่สำหรับเวอร์ชัน SRAS ใหม่
`project validate` ตรวจอินสแตนซ์และ lockfile
`project resolve` แสดงเกตที่ยังไม่ประเมิน
ไม่มี ID, ฟิลด์ schema หรือการตัดสินเกตใดต้องเปลี่ยนสำหรับ release นี้

โปรเจกต์ที่ใช้เวอร์ชันอื่นควรอ่าน migration note ของเวอร์ชันนั้น

## ข้อจำกัด

ข้อจำกัดเหล่านี้เป็นส่วนหนึ่งของ release ไม่ใช่ footnote:

- **คำแปลไทยยัง partial** — ข้อกำหนด active 167 ข้อเป็น
  `translation_status: partial` และ `machine_translated: true`
  ยังไม่มีผู้ทบทวนภาษาไทยที่มีชื่อยืนยัน
- **ไม่มีการอ้างการทบทวนภายนอกหรือโดยมนุษย์** — เนื้อหาเขียนและตรวจโดย AI
  โปรเจกต์ที่นำไปใช้อาจจัดให้มีการทบทวนของตนเอง
- **ทะเบียนยัง unverified** — เป็นดัชนีข้อเท็จจริง ไม่ใช่คำแนะนำทางกฎหมาย
  หรือข้อสรุป compliance
- **ข้อกังวลทางกฎหมายเป็น desk research** — #128–#131 รวบรวมแหล่งและคำถาม
  ไม่ได้ตัดสินว่าแหล่งใดใช้กับโปรเจกต์
- **Template เป็นแบบกลาง** — ไม่มีกฎจัดซื้อ การเก็บรักษา หรือการอนุมัติเฉพาะ
  หน่วยงาน เพิ่มกฎเหล่านั้นใน instance ส่วนตัว
- **ไม่มีการรับรองหรือข้ออ้าง compliance** — repository ไม่ได้ผ่านการรับรอง
  (accreditation) การ audit การอนุมัติจากหน่วยงานกำกับ หรือรับประกันว่าจะผ่าน
  การจัดซื้อ
- **ไม่มี service-level agreement** — maintainer ดูแลสาย v1.x ล่าสุดแบบ
  best effort

## เงื่อนไขของ release

template release จะถูกสร้างเมื่อ:

- issue ของ 0.10.0 ปิดครบและงาน concern-template เสร็จ
- #61 ตั้งเวอร์ชันเป็น 1.0.0 และอัปเดต release metadata
- #66 ลบวัสดุ bootstrap ชั่วคราว รันการตรวจครั้งสุดท้าย และปิด milestone
- release notes และ announcement ระบุข้อจำกัด
- `ci-ok` และ `pr-check / check` เขียวบน `main`
- `oss-kit doctor` รายงานว่าไม่มีความคลาดเคลื่อน

ไม่มีการทบทวนภาษาไทยโดยมนุษย์ การทบทวนภายนอก หรือการทบทวนทางกฎหมายเป็น
เงื่อนไขของ release

หากเงื่อนไขใดไม่ครบตอนเตรียม release หน้านี้จะยังเป็น draft และ milestone จะไม่ถูกปิดเพื่อทำให้ checklist ดูเสร็จ

## สรุปสำหรับผู้อ่านภายนอก

> SRAS starter kit เป็น template แบบเปิดสำหรับการส่งมอบซอฟต์แวร์ที่อิงหลักฐาน
> มีข้อกำหนด active 167 ข้อ ครอบคลุม Core, technical module ห้าโมดูล และ
> overlay ภาคธุรกิจประเทศไทยสี่ชุด พร้อม register 27 รายการ crosswalk เชิงข้อมูล
> เจ็ดชุด CLI สำหรับ project instance reference pages แบบ deterministic และ
> content guard ใช้ได้โดยมีข้อจำกัด: คำแปลไทยเป็น machine-assisted และ partial
> ทะเบียนยัง unverified และไม่มีการอ้างการทบทวนภายนอกหรือโดยมนุษย์
> ไม่ใช่การรับรอง ไม่ใช่คำแนะนำทางกฎหมาย และไม่ใช่หลักฐานของ compliance
> ทีมควรบันทึกขอบเขต หลักฐาน claim และความเสี่ยงของตนเองใน project instance
> ส่วนตัว

สรุปนี้ใช้ข้อความที่ตรวจสอบได้จาก repository เท่านั้น ไม่มีชื่อลูกค้า โปรเจกต์จริง
หรือผู้ทบทวน
