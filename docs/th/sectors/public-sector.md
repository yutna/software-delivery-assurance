# ภาครัฐ

overlay `TH-PUB` เพิ่มข้อกำหนด assurance 12 ข้อ สำหรับหน่วยงานของรัฐ
รัฐวิสาหกิจ และผู้ขายที่ให้บริการภาครัฐดิจิทัลในประเทศไทย

overlay นี้เป็นส่วนเพิ่มจาก SRAS Core ไม่ใช่กฎหมายจัดซื้อจัดจ้าง และไม่ใช่
คำแนะนำทางกฎหมาย ใช้เป็นรายการตรวจสอบว่าหลักฐานใดควรมีก่อนส่งมอบ และบันทึก
ช่องว่างที่ต้องแก้

> หน้านี้เป็นฉบับภาษาไทยที่แปลโดยเครื่องและปรับถ้อยคำ ยังไม่ผ่านการตรวจทาน
> โดยมนุษย์ จึงยังคง `translation_status: partial` และ `machine_translated: true`

## เหมาะกับใคร

- ทีมดิจิทัลของหน่วยงานรัฐที่กำลังพัฒนาหรือจัดหาบริการดิจิทัล
- รัฐวิสาหกิจที่มีโครงการเทคโนโลยีสารสนเทศ
- ผู้ขายที่ต้องส่งหลักฐานให้หน่วยงานผู้ว่าจ้าง
- ทีม bid ที่ต้องตอบข้อกำหนดด้าน assurance
- ผู้ตรวจประเมินภายในที่ต้องเตรียมหลักฐานก่อนเปิดบริการ

## สิ่งที่ overlay ครอบคลุม

| หัวข้อ                     | สิ่งที่ต้องมี                                          |
| -------------------------- | ------------------------------------------------------ |
| การจัดซื้อและสัญญา         | หลักฐานการจัดซื้อจัดจ้างและสัญญาสำหรับแต่ละบริการ      |
| การเก็บรักษาบันทึก         | ตารางเก็บรักษาที่อนุมัติและหลักฐานการปฏิบัติตาม        |
| Accessibility              | เป้าหมาย accessibility ที่ตกลงและหลักฐานการทดสอบ       |
| ภาษาไทย                    | เนื้อหาบริการที่ผ่านการตรวจทานโดยเจ้าของภาษา           |
| Open data                  | การควบคุมคุณภาพ สิทธิ์การใช้งาน และความเป็นส่วนตัว     |
| Hosting และ data residency | ที่ตั้งและข้ออนุมัติที่เกี่ยวข้อง                      |
| บุคลากร                    | การตรวจสอบบุคลากรให้ตรงกับสิทธิ์และความอ่อนไหวของบทบาท |
| ความต่อเนื่อง              | การทดสอบบริการสาธารณะที่สำคัญอย่างน้อยปีละครั้ง        |
| การดำเนินการทางปกครอง      | ความสามารถตรวจสอบย้อนหลังและระบุผู้รับผิดชอบ           |
| การเปลี่ยนแปลงร่วม         | บันทึกการเปลี่ยนแปลงระหว่างหน่วยงานและผู้ขาย           |
| การสื่อสารเหตุการณ์        | template และ owner ที่อนุมัติแล้วสำหรับการแจ้งประชาชน  |
| Privacy impact             | การประเมินผลกระทบความเป็นส่วนตัวก่อนเปิดตัว            |

## ข้อกำหนดทั้ง 12 ข้อ

| ID           | ข้อกำหนดโดยสรุป                                                    |
| ------------ | ------------------------------------------------------------------ |
| `TH-PUB-001` | หลักฐานการจัดซื้อจัดจ้างและสัญญาถูกเก็บสำหรับแต่ละบริการ           |
| `TH-PUB-002` | การเก็บรักษาบันทึกเป็นไปตามกำหนดเวลาที่อนุมัติ                     |
| `TH-PUB-003` | บริการสาธารณะเป็นไปตามเป้าหมาย accessibility ที่ตกลง               |
| `TH-PUB-004` | เนื้อหาบริการภาษาไทยผ่านการตรวจทานโดยเจ้าของภาษา                   |
| `TH-PUB-005` | open data เผยแพร่พร้อมการควบคุมคุณภาพ สิทธิ์ และความเป็นส่วนตัว    |
| `TH-PUB-006` | ที่ตั้ง hosting และ data residency ถูกบันทึกและอนุมัติ             |
| `TH-PUB-007` | การตรวจสอบบุคลากรตรงกับสิทธิ์และความอ่อนไหวของบทบาท                |
| `TH-PUB-008` | ความต่อเนื่องของบริการสาธารณะที่สำคัญทดสอบอย่างน้อยปีละครั้ง       |
| `TH-PUB-009` | การดำเนินการทางปกครองตรวจสอบได้และระบุผู้รับผิดชอบได้              |
| `TH-PUB-010` | การเปลี่ยนแปลงระหว่างหน่วยงานและผู้ขายใช้บันทึกร่วมกัน             |
| `TH-PUB-011` | การสื่อสารเหตุการณ์ต่อประชาชนมี template และ owner อนุมัติแล้ว     |
| `TH-PUB-012` | การประเมินผลกระทบความเป็นส่วนตัวได้รับการอนุมัติก่อนเปิดตัวสาธารณะ |

ถ้อยแถลงเต็ม ความคาดหวังด้านหลักฐาน และแนวทางการประเมินอยู่ใน
[reference ภาครัฐ](../../en/reference/overlays/TH-PUB.md) ที่ generate ไว้

## วิธีใช้ overlay นี้กับโปรเจกต์

1. เลือก overlay `TH-PUB` ใน `assurance.yaml`
2. ตรวจว่า instance ประเมิน `TH-PUB-001` หรือไม่ ถ้าใช่ ให้กรอก
   `scope.public_sector` พร้อม `contracting_authority` และ
   `contract_reference`
3. ใช้ owner map เพื่อกำหนดผู้รับผิดชอบหลักฐานแต่ละประเภท
4. เก็บหลักฐานจริงในระบบส่วนตัว และใส่เฉพาะ reference ใน evidence index
5. บันทึกช่องว่างและความเสี่ยงที่ยังแก้ไม่ได้ลง risk register
6. ให้ sponsor ลงนาม assessment หลังตรวจ claims และ risks แล้ว

ตัวอย่างของ `scope.public_sector`:

```yaml
scope:
  public_sector:
    contracting_authority: Synthetic public authority
    contract_reference: SYNTH-CONTRACT-001
```

ตัวอย่างสาธารณะต้องใช้หน่วยงาน synthetic เท่านั้น ห้ามใส่ชื่อหน่วยงานจริง

## สิ่งที่ overlay ไม่ครอบคลุม

- คำแนะนำเรื่องกฎหมายจัดซื้อจัดจ้างหรือขั้นตอนการอุทธรณ์
- ความเห็นทางกฎหมายเรื่อง data residency
- ตารางการเก็บรักษาบันทึกสำหรับทุกหน่วยงาน
- การรับประกันความสอดคล้องด้าน accessibility
- ถ้อยแถลงว่าบริการได้รับอนุมัติให้เปิดตัวสาธารณะ
- การตัดสินใจทาง Procurement หรือราคา
- การรับรองจากหน่วยงานกำกับดูแล

## คำถามกฎหมายที่ยังเปิดอยู่

คำถามเหล่านี้กระทบการนำ overlay ไปใช้กับโปรเจกต์จริง และยังไม่มีคำตอบในคลัง:

| Issue | คำถาม                                                                     | Requirement  |
| ----- | ------------------------------------------------------------------------- | ------------ |
| #131  | WCAG เวอร์ชันและระดับใดใช้กับบริการภาครัฐไทย และแตกต่างตามหน่วยงานหรือไม่ | `TH-PUB-003` |
| #130  | licence ใดยอมรับได้สำหรับ open government data                            | `TH-PUB-005` |

ทีมควรตัดสินใจสำหรับโปรเจกต์ของตนเองโดยปรึกษาผู้เชี่ยวชาญ และบันทึกคำตอบไว้ใน
instance ส่วนตัว ไม่ใช่ใน repository นี้

## รายการทะเบียนที่เกี่ยวข้อง

overlay ภาครัฐอ้างอิง `TH-CCA-001`, `TH-CYBER-001`, `TH-DGA-001`,
`TH-PDPA-001` และ `TH-PROC-001` รวมถึง WCAG 2.2 อ่าน
[ดัชนีทะเบียน](../registers/index.md) สำหรับแหล่งอ้างอิงทางการและข้อจำกัดใน
การตรวจทาน
