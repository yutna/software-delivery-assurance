# สรุปการนำร่องและการ triage

หน้านี้รวบรวมการนำร่องภายในสองครั้ง disposition ของทุก finding สถานะการทบทวน
ภายนอก และคำถามทางกฎหมายที่ยังเปิดอยู่ ครอบคลุม SRAS 0.8.0 และโปรเจกต์ synthetic
เท่านั้น

## สถานะ ณ 2026-10-28

- การนำร่องเสร็จ: 2 ครั้ง (การเงินและภาครัฐ)
- Findings: 18 — high 6, medium 8, low 4
- แก้ ณ v0.9.0 ใน #59: 9
- เลื่อน ณ v0.9.0 พร้อม issue ติดตาม: 5
- ข้อกังวลทางกฎหมายและกฎระเบียบ: 4 (desk research note; โปรเจกต์ต้องตัดสินใจเอง)
- การทบทวนภายนอก: ไม่มี ยังไม่มีผู้ตรวจทานภายนอก
- การตรวจที่ทำ: AI ตรวจเองเมื่อ 2026-10-28 owner ยอมรับสำหรับขั้นตอนการทบทวนของ
  v0.9.0 ไม่ใช่การทบทวนอิสระ โดยมนุษย์ หรือทางกฎหมาย

หลัง release v0.9.0 มีการแก้ finding ที่เลื่อนไว้ทั้งห้ารายการ: PF-02 โดย #140,
PF-03 โดย #126, PS-04 โดย #141, PS-06 โดย #135 และ PS-07 โดย #134 สถานะปัจจุบัน
คือแก้แล้ว 14 รายการ ยังเลื่อน 0 รายการ และเป็นคำถามกฎหมายที่เปิดอยู่ 4 รายการ
การเลื่อนเดิมยังคงอยู่ด้านล่างเป็นประวัติ ไม่ถูกเขียนใหม่

owner ยืนยันว่าไม่มีผู้ตรวจทานภายนอก หน้านี้บันทึกข้อเท็จจริงนั้นแทนการสร้างชื่อ
วันที่ หรือการ sign-off ที่ไม่มีจริง

## วิธีการ triage

ความรุนแรงสะท้อนผลต่อผู้อ่านหรือต่อ workflow ที่จัดทำเอกสารไว้ ไม่ใช่ปริมาณงานใน
การแก้

- **High:** อาจทำให้ผู้อ่านเข้าใจ coverage ผิดหรือทำให้ workflow ที่จัดทำเอกสารไว้
  ทำไม่ได้ ต้องแก้ก่อน stable release
- **Medium:** การตรวจสอบไม่ครบหรือข้อกำหนดคลุมเครือ ต้องแก้หรือติดตามพร้อม owner ที่
  ระบุชื่อก่อน stable release
- **Low:** เอกสารคลาดเคลื่อนหรือปัญหาเล็กที่มีทางแก้ชัดเจน

ทุก finding มี owner หนึ่งคน เนื่องจากมี maintainer คนเดียว owner คือ `@yutna`
ทั้ง 18 finding. finding จะไม่ถูกปิดด้วยความเงียบ: ต้องเป็น `fixed`, `deferred`
พร้อม issue หรือ `open legal question` พร้อม issue

## รายละเอียด disposition

### แก้ใน #59

เก้า finding เป็นข้อบกพร่องด้านเนื้อหา ข้อมูล หรือ validation ที่เข้ากับ pipeline
เดิม:

- PF-01 และ PS-01: ทำให้ตัวอย่างภาคธุรกิจทั้งสี่เป็น project instance ที่สมบูรณ์
  และ parse ใน tests
- PF-04 และ PS-02: ระบุตัวหารของข้อกำหนดและ gate ที่ resolve ได้ในแต่ละตัวอย่าง
  และ test ว่าข้อความตรงกับชุดที่คำนวณได้
- PF-05: ปฏิเสธ `freshness_status: current` เมื่อ evidence หมดอายุก่อนวันประเมิน
- PF-06 และ PF-07: แก้คำอธิบาย lockfile และเวอร์ชันตัวอย่างที่ค้างในทั้งสองภาษา
- PF-08: ใช้วันตามปฏิทินท้องถิ่นเมื่อสร้าง instance
- PF-09: แก้รายการแหล่งอ้างอิงในหน้ากาศการเงิน

### เลื่อน ณ v0.9.0

ยังคง disposition เดิมเป็นประวัติ

finding ที่เลื่อนทั้งห้ารายการมี resolution แล้ว ไม่มีข้อใดเป็นการยกเว้น gate

## บันทึกการตรวจ

**การทบทวนภายนอก: ไม่มี** ยังไม่มีผู้ตรวจทานภายนอก ณ 2026-10-28

**AI ตรวจเอง: เสร็จเมื่อ 2026-10-28** ผู้ตรวจคือ AI execution agent (DeepSeek
V4.1 Flash ผ่าน OpenCode) ภายใต้คำสั่งของ owner ไม่ใช่ผู้ตรวจทานภายนอก ไม่ใช่มนุษย์
และไม่ใช่ผู้ตรวจทานกฎหมายที่มีคุณสมบัติ owner ยอมรับการตรวจนี้สำหรับขั้นตอนการ
ทบทวนของ v0.9.0

ขอบเขต: รายงานการนำร่องทั้งสอง, disposition ทั้ง 18 ข้อ, หลักฐานความพร้อม, release
metadata และ gates ของ docs และ content

ผล: ทุก finding มี owner และ disposition; finding ที่แก้มี tests และ finding ที่
เลื่อนมี issue; examples validate เป็น project instance; version ตรงกัน; และ gates
ทั้งหมดผ่าน ไม่พบข้อบกพร่องใหม่ที่บล็อก release v0.9.0

ข้อจำกัด: การตรวจนี้ไม่เป็นอิสระ ไม่สามารถยืนยันความหมายทางกฎหมายหรือสถานะปัจจุบัน
ของแหล่งทางการ และไม่ใช่สิ่งทดแทนการทบทวนทางกฎหมายหรือการทบทวนภายนอก รายการ
ทะเบียนยังเป็น `unverified` ไม่มีหน้าใดอ้างการทบทวนภายนอกหรือการตรวจสอบอิสระ และ
release notes ของ v0.9.0 ไม่กล่าวอ้างการทบทวนภายนอก ตอนตรวจ v0.9.0 การทบทวนโดย
มนุษย์ภายนอกถูกบันทึกเป็น blocker ของ v1.0.0 แต่การ re-scope 0.10.0 ยกเลิกเงื่อนไข
นั้นแล้ว (PR #175, #176 และ #177) template release 1.0.0 จึงไม่ได้กำหนดให้ต้องมี
และไม่กล่าวอ้างการทบทวนภายนอก

## ข้อกังวลทางกฎหมายและกฎระเบียบ

ข้อกังวลเหล่านี้มาจากการนำร่อง. repository บันทึกคำถาม แหล่งอ้างอิงทางการ และ
ประเด็นที่โปรเจกต์ต้องตัดสินใจ ไม่ได้ตอบแทนโปรเจกต์
[ข้อกังวลทางกฎหมาย](../governance/legal-concerns.md) มี desk research note
ข้อจำกัดของการวิจัย และ template บันทึกการตัดสินใจของโปรเจกต์

issue จะปิดเมื่อเผยแพร่ concern note แล้ว การปิดหมายถึง "เผยแพร่ research note"
ไม่ใช่ "ตอบคำถามทางกฎหมายแล้ว" และไม่ใช่ "แหล่งอ้างอิงนี้ใช้กับโปรเจกต์ของคุณ"
โปรเจกต์ที่ต้องการข้อสรุปทางกฎหมายต้องขอคำแนะนำที่มีคุณสมบัติเอง

- **#129:** กฎหมายใดกำหนดระยะเวลาเก็บรักษาบันทึกธุรกรรมขั้นต่ำ และแตกต่างตามประเภท
  บริการหรือไม่ (`TH-FIN-004`)
- **#128:** กฎ ธปท. ที่เผยแพร่ระบุว่าการใช้ cloud หรือ outsourcing แบบ material
  ต้องแจ้งหรือขออนุมัติล่วงหน้าอย่างไร (`TH-FIN-003`)
- **#131:** มาตรฐานและแนวทางไทยระบุ WCAG เวอร์ชันและระดับใดสำหรับบริการภาครัฐ
  (`TH-PUB-003`)
- **#130:** แนวทางไทยยอมรับเงื่อนไข licence ใดสำหรับข้อมูลเปิดภาครัฐ (`TH-PUB-005`)

ข้อกำหนดทั้งสี่คง `review_status: draft` ไม่มีการระบุระยะเวลา ขั้นตอนอนุมัติ ระดับ
conformance หรือ licence ในไลบรารี

## ข้อจำกัดของหลักฐานการนำร่อง

- การนำร่องสองครั้ง ผู้ประเมินหนึ่งคน ข้อมูล synthetic ไลบรารีหนึ่งเวอร์ชัน (0.8.0)
- ไม่ได้ประเมินโปรเจกต์จริง หลักฐานจริง หรือกระบวนการผลิตจริง
- ไม่ได้ทดสอบ lite profile, module ทั้งหมด, overlay ทั้งหมด หรือทะเบียน EU และ
  ASEAN
- ไม่มีผู้ตรวจทานภายนอกและไม่มีผู้ตรวจทานกฎหมายที่มีคุณสมบัติเข้าร่วม
- จำนวนที่ resolve ได้ขึ้นกับ tier และ selection จึงเป็นหลักฐานของตัวอย่างเท่านั้น
  ไม่ใช่ข้ออ้าง coverage โดยทั่วไป
